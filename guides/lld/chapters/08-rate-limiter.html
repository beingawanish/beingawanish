Chapter 8: Rate Limiter

Type every file in order. Run each checkpoint before moving on. All commands run from the project folder (the one holding rate_limiter/ and tests/). Python 3.13, stdlib only.

The first seven chapters modelled businesses: lots, lifts, libraries, cars. This one models a piece of infrastructure, and it is one of the most-asked LLD problems of 2026. Every public API has a rate limiter in front of it. Every LLM gateway meters tokens per key. Every agent framework hammers some endpoint until a 429 tells it to stop. The problem looks small, a counter and an if. It isn't. Five algorithms compete for the job, the counter is shared by every thread in the process, and the interviewer will eventually ask you to run it on twenty servers at once.

1. The problem

An API serves anonymous visitors, signed-in users, and partners calling with API keys. Each kind of caller gets a limit: so many requests per window of time. Paying tiers get more. When a caller goes over, the API answers 429 Too Many Requests and tells them when to come back. The limiter must be fast, correct under concurrent requests, cheap in memory when a million different IPs pass through, and swappable between algorithms without touching the code that calls it.

You build the limiter itself, not the web server. Its job is to answer one question per request — "may this pass?" — and to answer it with enough detail that the HTTP layer can write the response headers.

2. Requirements

Clarifying questions to ask first (with the answers an interviewer would give):

  • What do we limit on: user, API key, IP? All three. A request is limited by one key, chosen by the caller: user id when signed in, API key for machine clients, IP for anonymous traffic.
  • Same limit for everyone? No. Tiers: anonymous, free, pro, partner. Each scope has a default tier; an explicit tier overrides it.
  • Which algorithm? "Which would you pick, and why?" This is the real question. Expect to compare at least token bucket, fixed window and sliding window, and to name the trade-off of each.
  • Are bursts acceptable? For paid tiers, yes: 1,000 per minute on average, up to 2,000 at once.
  • Does every request cost the same? Not in 2026. An LLM endpoint costs by tokens, a bulk export by rows. Support a per-request cost.
  • What do we send back on a denial? HTTP 429 with Retry-After, plus RateLimit-Limit, RateLimit-Remaining and RateLimit-Reset on every response.
  • One process or many? Start with one. Then expect "now there are twenty API servers".
  • What if the counter store is down? Ask whether the business prefers to fail open (let traffic through) or fail closed (refuse it). Make it a config flag.
  • How many distinct keys? Potentially millions of IPs, most seen once. Idle keys must not live forever.

Functional

  • Decide a request for a ClientKey(scope, value, tier) with a cost (default 1). Return a Decision: allowed, remaining, retry_after, reset_after.
  • Five algorithms behind one interface: token bucket, leaky bucket, fixed window, sliding-window log, sliding-window counter. The rule picks the algorithm.
  • Tiers come from config: name, limit, window, algorithm, optional burst.
  • Map a decision to an HTTP status (200 or 429) and response headers.
  • Purge idle keys, on demand and from a background thread.
  • On a store failure: fail open or fail closed, as configured.

Non-functional

  • Thread-safe: forty threads racing on one key with a limit of 10 let exactly 10 through, for every algorithm.
  • Time is injectable. No algorithm reads the system clock; tests never sleep.
  • State lives behind a storage interface, so a Redis-backed store can replace the dict.
  • O(1) memory per key, except the sliding log, which is O(limit) by design.
  • Typed exceptions; a denial is a normal result, not an exception.
  • Stdlib only.

5. Key design decisions

  1. An algorithm is a pure step function. apply(state, rule, now, cost) returns the next state and a Decision. It reads no clock, takes no lock, does no I/O. That one constraint pays three times. Tests call it directly with made-up timestamps. Thread safety becomes the store's job alone. And the same step can later run inside Redis, because it has nothing in it that only works in Python's memory.
  2. The store owns atomicity. StateStore.update(key, now, ttl, step) reads the state, runs the step, writes the result and sets an expiry, as one atomic unit. "Check, then act" is the classic race in a rate limiter: two threads both read 9 of 10, both write 10, and 11 requests pass. Putting the whole read-modify-write behind one method means no caller can split it by accident. In memory that unit is a lock. In Redis it is a Lua script.
  3. A denial is a value, not an exception. A 429 is the limiter working, not failing. Decision(allowed=False, retry_after=…) flows through the same code path as an allow. Exceptions are kept for things that really are wrong: a broken config, a blank key, a dead store.
  4. One Decision for all five algorithms. The HTTP layer calls decision.headers() and never learns which algorithm ran. Swapping fixed window for token bucket on the free tier is a config change, not a code change.
  5. Each algorithm knows its own memory horizon. idle_ttl(rule) says when a key's state becomes identical to a brand-new key's. A token bucket is full again after capacity / rate seconds. A sliding counter needs two whole windows. The store expires each key at exactly that point, plus a grace period. That makes cleanup safe by construction: deleting an idle key can never hand a client a quota it hadn't earned back.
  6. The rule is part of the storage key. rl:{rule}:{algorithm}:{scope}:{value}. A user who upgrades from free to pro starts a fresh pro bucket instead of inheriting a half-empty free one. Two algorithms never read each other's state shapes.
  7. Monotonic time, injected. Wall-clock time jumps: NTP corrections, a VM resuming. A token bucket fed a clock that jumps forward refills for free. The production clock is time.monotonic(), and every algorithm clamps a negative elapsed time to zero anyway.

The five algorithms, side by side. This is the table the interviewer is fishing for. Learn the "why" column, not just the names.

Patterns, and why each earns its place. Strategy for the algorithms: five ways to answer the same question, chosen per rule. Repository, in the form of StateStore, for state: the dict becomes Redis and the limiter never notices. A registry (dict[str, RateLimitAlgorithm]) instead of an if algorithm == … chain, so a sixth algorithm is a new class plus one dictionary entry.

Step 1 — The error hierarchy

Goal: name every way the limiter can fail. Notice what is missing: there is no RateLimitExceededError.

Type rate_limiter/errors.py:

"""The rate limiter's failure modes, one type per recovery path.

A denied request is NOT an error: it is a normal Decision with allowed=False.
Exceptions are reserved for bad configuration, bad input, and a broken store.
"""


class RateLimiterError(Exception):
    """Root of every rate-limiter failure. Catch this to catch them all."""


class ConfigError(RateLimiterError):
    """The limiter was wired with configuration that can never work."""


class InvalidRuleError(ConfigError):
    """A LimitRule has a non-positive limit, window, or a misplaced burst."""


class UnknownAlgorithmError(ConfigError):
    """A rule names an algorithm nobody registered."""


class InvalidRequestError(RateLimiterError):
    """The caller passed input the limiter refuses to evaluate."""


class InvalidKeyError(InvalidRequestError):
    """The client key is blank."""


class InvalidCostError(InvalidRequestError):
    """The request cost is below 1 or larger than the bucket could ever hold."""


class UnknownTierError(InvalidRequestError):
    """The client asked for a tier, or has a scope, with no configured rule."""


class StoreError(RateLimiterError):
    """The state store failed (in a distributed setup: Redis timed out)."""


class LimiterUnavailableError(RateLimiterError):
    """The store failed and the limiter is configured to fail closed."""

What to notice. Two families with two different owners. ConfigError is the operator's fault and should stop the process at startup. InvalidRequestError is the caller's fault and maps to a 400. StoreError is the infrastructure's fault, and the limiter decides what to do about it from config. A caller that catches InvalidRequestError will never accidentally swallow a dead Redis.

Step 2 — Configuration: rules, tiers and scopes

Goal: put every number the limiter enforces in one validated place.

Type rate_limiter/config.py:

"""Configuration: algorithms, key scopes, limit rules, and the tier table.

Every number the limiter enforces lives here. The algorithms read a LimitRule;
they never contain a literal limit or window of their own.
"""
from dataclasses import dataclass, field
from enum import StrEnum

from .errors import ConfigError, InvalidRuleError


class Algorithm(StrEnum):
    """Names of the built-in algorithms. A custom one can use any other string."""

    TOKEN_BUCKET = "token_bucket"
    LEAKY_BUCKET = "leaky_bucket"
    FIXED_WINDOW = "fixed_window"
    SLIDING_LOG = "sliding_log"
    SLIDING_COUNTER = "sliding_counter"


# Only bucket algorithms have a capacity separate from their refill rate.
BUCKET_ALGORITHMS: frozenset[str] = frozenset(
    {Algorithm.TOKEN_BUCKET, Algorithm.LEAKY_BUCKET}
)


class KeyScope(StrEnum):
    """What a limit is counted against."""

    USER = "user"
    API_KEY = "api_key"
    IP = "ip"


@dataclass(frozen=True, slots=True)
class LimitRule:
    """`limit` requests per `window_seconds`, enforced by `algorithm`.

    `burst` (bucket algorithms only) sets the bucket size separately from the
    average rate: 100 per minute on average, but up to 300 at once.
    """

    name: str
    limit: int
    window_seconds: float
    algorithm: str = Algorithm.TOKEN_BUCKET
    burst: int | None = None

    def __post_init__(self) -> None:
        if not self.name.strip():
            raise InvalidRuleError("rule name must not be blank")
        if self.limit < 1:
            raise InvalidRuleError(f"{self.name}: limit must be >= 1, got {self.limit}")
        if self.window_seconds <= 0:
            raise InvalidRuleError(
                f"{self.name}: window_seconds must be > 0, got {self.window_seconds}"
            )
        if self.burst is not None:
            if self.algorithm not in BUCKET_ALGORITHMS:
                raise InvalidRuleError(
                    f"{self.name}: burst only applies to bucket algorithms, "
                    f"not {self.algorithm}"
                )
            if self.burst < 1:
                raise InvalidRuleError(f"{self.name}: burst must be >= 1, got {self.burst}")

    @property
    def capacity(self) -> int:
        """The most requests that can pass at one instant."""
        return self.burst if self.burst is not None else self.limit

    @property
    def rate_per_second(self) -> float:
        """The long-run average rate the rule allows."""
        return self.limit / self.window_seconds


def _default_tiers() -> dict[str, LimitRule]:
    rules = (
        LimitRule("anonymous", 30, 60.0, Algorithm.SLIDING_COUNTER),
        LimitRule("free", 100, 60.0, Algorithm.TOKEN_BUCKET),
        LimitRule("pro", 1_000, 60.0, Algorithm.TOKEN_BUCKET, burst=2_000),
        LimitRule("partner", 100_000, 86_400.0, Algorithm.FIXED_WINDOW),
    )
    return {rule.name: rule for rule in rules}


def _default_scope_tiers() -> dict[KeyScope, str]:
    return {KeyScope.IP: "anonymous", KeyScope.USER: "free", KeyScope.API_KEY: "free"}


@dataclass(frozen=True)
class RateLimiterConfig:
    """The tier table plus the limiter's operational knobs.

    tiers                  -- tier name -> rule; the key must equal rule.name
    default_tier_by_scope  -- tier used when a client key carries no tier
    idle_grace_seconds     -- extra time an idle key is kept past its reset point
    sweep_interval_seconds -- how often the background sweeper purges idle keys
    fail_open              -- on a store failure: allow (True) or refuse (False)
    """

    tiers: dict[str, LimitRule] = field(default_factory=_default_tiers)
    default_tier_by_scope: dict[KeyScope, str] = field(default_factory=_default_scope_tiers)
    idle_grace_seconds: float = 5.0
    sweep_interval_seconds: float = 30.0
    fail_open: bool = True

    def __post_init__(self) -> None:
        if not self.tiers:
            raise ConfigError("at least one tier is required")
        for tier_name, rule in self.tiers.items():
            if tier_name != rule.name:
                raise ConfigError(f"tier key {tier_name!r} does not match rule {rule.name!r}")
        for scope, tier_name in self.default_tier_by_scope.items():
            if tier_name not in self.tiers:
                raise ConfigError(f"scope {scope} defaults to unknown tier {tier_name!r}")
        if self.idle_grace_seconds < 0:
            raise ConfigError("idle_grace_seconds must be >= 0")
        if self.sweep_interval_seconds <= 0:
            raise ConfigError("sweep_interval_seconds must be > 0")

What to notice. LimitRule.algorithm is typed str, not Algorithm. The enum is a set of well-known names, and because StrEnum members are strings they fit the field directly. A custom algorithm can still register under any other name without editing this file. burst is rejected on window algorithms: a fixed window has no bucket for a burst to fill, and silently ignoring the field would be worse than refusing it.

Step 3 — The clock

Goal: make time a seam. The limiter is nothing but arithmetic on time, so this seam matters more here than in any earlier chapter.

Type rate_limiter/clock.py:

"""The injectable clock. Rate limiting is arithmetic on time, so time is a seam.

Times are plain float seconds from a monotonic source. Wall-clock time can jump
backwards (NTP, daylight saving); a limiter fed by it would refill buckets twice.
"""
import threading
import time
from abc import ABC, abstractmethod


class Clock(ABC):
    @abstractmethod
    def now(self) -> float:
        """Seconds since an arbitrary, fixed origin. Never decreases."""


class MonotonicClock(Clock):
    """Production clock: time.monotonic()."""

    def now(self) -> float:
        return time.monotonic()


class ManualClock(Clock):
    """Test clock that only moves when told to. Safe to share across threads."""

    def __init__(self, start: float = 0.0) -> None:
        self._now = start
        self._lock = threading.Lock()  # guards _now

    def now(self) -> float:
        with self._lock:
            return self._now

    def advance(self, seconds: float) -> None:
        if seconds < 0:
            raise ValueError(f"a monotonic clock cannot go back ({seconds})")
        with self._lock:
            self._now += seconds

What to notice. The clock returns float seconds, not a datetime. A rate limiter never needs the calendar; it needs differences. Floats make elapsed * rate one multiplication. ManualClock has a lock because the concurrency test shares it across forty threads.

Checkpoint:

Step 4 — The decision, and its HTTP face

Goal: type the one object every algorithm returns, and its mapping to status code and headers.

Type rate_limiter/decision.py:

"""The answer to "may this request pass?", and how it maps onto HTTP.

Every algorithm returns the same Decision, so the HTTP layer never needs to
know which algorithm made it.
"""
import math
from dataclasses import dataclass
from http import HTTPStatus


@dataclass(frozen=True, slots=True)
class Decision:
    """One rate-limit verdict.

    allowed     -- may the request proceed?
    limit       -- the most requests that can pass at once under this rule
    remaining   -- how many more would pass right now
    retry_after -- seconds until this same request would pass (0 when allowed)
    reset_after -- seconds until the key is back to a full quota
    delay       -- leaky bucket only: wait this long before doing the work
    degraded    -- True when the store failed and the limiter failed open
    """

    allowed: bool
    limit: int
    remaining: int
    retry_after: float
    reset_after: float
    delay: float = 0.0
    degraded: bool = False

    @property
    def status_code(self) -> int:
        return int(HTTPStatus.OK if self.allowed else HTTPStatus.TOO_MANY_REQUESTS)

    def headers(self) -> dict[str, str]:
        """RateLimit-* response headers, plus Retry-After on a 429.

        HTTP wants whole seconds, so times round UP: telling a client to come
        back in 0 seconds when the true answer is 0.3 guarantees another 429.
        A degraded decision sends no headers rather than invented numbers.
        """
        if self.degraded:
            return {}
        headers = {
            "RateLimit-Limit": str(self.limit),
            "RateLimit-Remaining": str(self.remaining),
            "RateLimit-Reset": str(_whole_seconds(self.reset_after)),
        }
        if not self.allowed:
            headers["Retry-After"] = str(max(1, _whole_seconds(self.retry_after)))
        return headers


def _whole_seconds(seconds: float) -> int:
    # Round to milliseconds first so float dust (2.0000000001) doesn't add a second.
    return math.ceil(round(seconds, 3))

What to notice. Rounding direction is a correctness issue here, not style. Retry-After: 0 for a true wait of 0.3 seconds invites an instant retry and a second 429. Rounding up, with a floor of 1, sends the client back when the request will actually pass. The RateLimit-* names follow the IETF httpapi rate-limit headers draft; many APIs still send the older X-RateLimit-* spellings, and adding them is a one-line change in this one method.

d = Decision(allowed=False, limit=100, remaining=0, retry_after=2.4, reset_after=30.0)
print(d.status_code, d.headers())"

Step 5 — Five algorithms, one interface

Goal: type the RateLimitAlgorithm contract and all five implementations. This is the longest file in the chapter and the one interviewers probe hardest. Type it slowly.

Type rate_limiter/algorithms.py:

"""Five rate-limiting algorithms behind one interface.

Each algorithm is a pure function of (old state, rule, now, cost) to
(new state, decision). No clock, no lock, no I/O. That purity is what lets the
same step run inside an in-memory lock today and inside a Redis Lua script later.
"""
import math
from abc import ABC, abstractmethod
from collections import deque
from dataclasses import dataclass

from .config import Algorithm, LimitRule
from .decision import Decision


class RateLimitAlgorithm[S](ABC):
    """The contract every algorithm honours.

    apply()    -- decide one request and return the key's next state.
                  `state` is None for a key never seen (or already expired).
    idle_ttl() -- seconds after a key's last request at which its state is
                  indistinguishable from a fresh key. Past that, it can be deleted.
    """

    name: str

    @abstractmethod
    def apply(self, state: S | None, rule: LimitRule, now: float, cost: int) -> tuple[S, Decision]:
        ...

    @abstractmethod
    def idle_ttl(self, rule: LimitRule) -> float:
        ...


def _allow(rule: LimitRule, remaining: float, reset_after: float, delay: float = 0.0) -> Decision:
    return Decision(True, rule.capacity, max(0, math.floor(remaining)), 0.0, reset_after, delay)


def _deny(rule: LimitRule, remaining: float, retry_after: float, reset_after: float) -> Decision:
    return Decision(False, rule.capacity, max(0, math.floor(remaining)), retry_after, reset_after)


# --------------------------------------------------------------------------- buckets

@dataclass(frozen=True, slots=True)
class BucketState:
    level: float        # tokens left (token bucket) or water held (leaky bucket)
    updated_at: float


class TokenBucket(RateLimitAlgorithm[BucketState]):
    """A bucket of `capacity` tokens refilling at `rate_per_second`.

    Allows bursts up to capacity, then the average rate. Two floats per key.
    """

    name = Algorithm.TOKEN_BUCKET

    def apply(self, state: BucketState | None, rule: LimitRule, now: float,
              cost: int) -> tuple[BucketState, Decision]:
        capacity, rate = rule.capacity, rule.rate_per_second
        if state is None:
            tokens = float(capacity)
        else:
            elapsed = max(0.0, now - state.updated_at)  # never refill on a clock step back
            tokens = min(float(capacity), state.level + elapsed * rate)
        if tokens >= cost:
            tokens -= cost
            decision = _allow(rule, tokens, (capacity - tokens) / rate)
        else:
            decision = _deny(rule, tokens, (cost - tokens) / rate, (capacity - tokens) / rate)
        return BucketState(tokens, now), decision

    def idle_ttl(self, rule: LimitRule) -> float:
        return rule.capacity / rule.rate_per_second


class LeakyBucket(RateLimitAlgorithm[BucketState]):
    """A queue of `capacity` slots draining at `rate_per_second`.

    It shapes rather than polices: an admitted request gets a `delay`, the time
    its place in the queue takes to reach the front. Output is perfectly smooth.
    """

    name = Algorithm.LEAKY_BUCKET

    def apply(self, state: BucketState | None, rule: LimitRule, now: float,
              cost: int) -> tuple[BucketState, Decision]:
        capacity, rate = rule.capacity, rule.rate_per_second
        if state is None:
            level = 0.0
        else:
            elapsed = max(0.0, now - state.updated_at)
            level = max(0.0, state.level - elapsed * rate)
        if level + cost <= capacity:
            delay = level / rate
            level += cost
            decision = _allow(rule, capacity - level, level / rate, delay)
        else:
            decision = _deny(rule, capacity - level, (level + cost - capacity) / rate, level / rate)
        return BucketState(level, now), decision

    def idle_ttl(self, rule: LimitRule) -> float:
        return rule.capacity / rule.rate_per_second


# --------------------------------------------------------------------------- windows

@dataclass(frozen=True, slots=True)
class WindowState:
    window: int         # index of the window: floor(now / window_seconds)
    count: int


class FixedWindow(RateLimitAlgorithm[WindowState]):
    """A counter per aligned window. Cheapest of all, but up to 2x the limit
    can pass across a window boundary."""

    name = Algorithm.FIXED_WINDOW

    def apply(self, state: WindowState | None, rule: LimitRule, now: float,
              cost: int) -> tuple[WindowState, Decision]:
        size = rule.window_seconds
        window = math.floor(now / size)
        count = state.count if state is not None and state.window == window else 0
        until_next = (window + 1) * size - now
        if count + cost <= rule.limit:
            count += cost
            decision = _allow(rule, rule.limit - count, until_next)
        else:
            decision = _deny(rule, rule.limit - count, until_next, until_next)
        return WindowState(window, count), decision

    def idle_ttl(self, rule: LimitRule) -> float:
        return rule.window_seconds


@dataclass(slots=True)
class LogState:
    stamps: deque[float]   # one timestamp per admitted unit of cost, oldest first


class SlidingWindowLog(RateLimitAlgorithm[LogState]):
    """Exact: remembers every admitted request in the last window.

    Memory is O(limit) per key, so it suits small limits only.
    The deque is mutated in place; the store calls apply() under its lock.
    """

    name = Algorithm.SLIDING_LOG

    def apply(self, state: LogState | None, rule: LimitRule, now: float,
              cost: int) -> tuple[LogState, Decision]:
        size = rule.window_seconds
        stamps = deque() if state is None else state.stamps
        while stamps and stamps[0] <= now - size:   # the window is (now - size, now]
            stamps.popleft()
        if len(stamps) + cost <= rule.limit:
            stamps.extend([now] * cost)
            decision = _allow(rule, rule.limit - len(stamps), stamps[-1] + size - now)
        else:
            # The request fits once enough of the oldest entries have aged out.
            must_expire = len(stamps) + cost - rule.limit
            retry_after = stamps[must_expire - 1] + size - now
            decision = _deny(rule, rule.limit - len(stamps), retry_after, stamps[-1] + size - now)
        return LogState(stamps), decision

    def idle_ttl(self, rule: LimitRule) -> float:
        return rule.window_seconds


@dataclass(frozen=True, slots=True)
class CounterState:
    window: int
    current: int        # admitted in the current window
    previous: int       # admitted in the window before it


class SlidingWindowCounter(RateLimitAlgorithm[CounterState]):
    """Two counters and a weighted estimate of the sliding window.

    estimate = previous * (share of the previous window still inside the
    sliding window) + current. Near-exact, and O(1) memory per key.
    """

    name = Algorithm.SLIDING_COUNTER

    def apply(self, state: CounterState | None, rule: LimitRule, now: float,
              cost: int) -> tuple[CounterState, Decision]:
        size = rule.window_seconds
        window = math.floor(now / size)
        if state is None or state.window < window - 1:
            current, previous = 0, 0
        elif state.window == window - 1:
            current, previous = 0, state.current
        else:
            current, previous = state.current, state.previous
        elapsed = now - window * size
        estimate = previous * (size - elapsed) / size + current
        if estimate + cost <= rule.limit:
            current += cost
            decision = _allow(rule, rule.limit - estimate - cost,
                              self._reset_after(current, previous, elapsed, size))
        else:
            retry_after = self._retry_after(current, previous, elapsed, size, rule.limit, cost)
            decision = _deny(rule, rule.limit - estimate, retry_after,
                             self._reset_after(current, previous, elapsed, size))
        return CounterState(window, current, previous), decision

    @staticmethod
    def _retry_after(current: int, previous: int, elapsed: float, size: float,
                     limit: int, cost: int) -> float:
        room = limit - cost - current
        if room >= 0 and previous > 0:
            # Fits later in this window, once the previous window's weight decays:
            # previous * (size - t) / size <= room.
            return size * (1 - room / previous) - elapsed
        until_next = size - elapsed
        room_next = limit - cost
        if current <= room_next:
            return until_next
        # In the next window, this window's count decays the same way.
        return until_next + size * (1 - room_next / current)

    @staticmethod
    def _reset_after(current: int, previous: int, elapsed: float, size: float) -> float:
        if current > 0:
            return 2 * size - elapsed
        if previous > 0:
            return size - elapsed
        return 0.0

    def idle_ttl(self, rule: LimitRule) -> float:
        return 2 * rule.window_seconds


def default_algorithms() -> dict[str, RateLimitAlgorithm]:
    """The built-in registry, keyed by Algorithm name."""
    algorithms: tuple[RateLimitAlgorithm, ...] = (
        TokenBucket(), LeakyBucket(), FixedWindow(), SlidingWindowLog(), SlidingWindowCounter(),
    )
    return {algorithm.name: algorithm for algorithm in algorithms}

What to notice. Read the five apply methods as one family. Each one does the same three things: bring the state up to now (refill, drain, roll the window, drop old stamps), test whether cost fits, then build the next state and a Decision.

The interesting differences are in the retry_after arithmetic. Token bucket: the missing tokens divided by the refill rate. Fixed window: time to the next boundary. Sliding log: the moment the right old entry ages out. If one request needs three units and the log is full, three entries must leave, so the answer is the third-oldest stamp plus one window. The sliding counter is the subtle one. Either the previous window's weight decays enough within this window, or you wait for the next window, where today's count becomes tomorrow's decaying "previous". Both cases solve the same equation, previous × (size − t) / size + current + cost ≤ limit, for t.

The leaky bucket returns a delay on success. That is the real difference from the token bucket. Both keep "level and timestamp", but the token bucket polices (pass now or refuse), while the leaky bucket shapes (pass, but only after your turn in the queue).

"""The storage seam: where per-key state lives, and how it is updated atomically.

The whole contract is one method, update(): read a key's state, run the
algorithm's step on it, write the result back with an expiry, all as one atomic
unit. In memory that is a lock. In Redis it is a Lua script (see the chapter's
follow-ups); the limiter cannot tell the difference.
"""
import logging
import threading
from abc import ABC, abstractmethod
from collections.abc import Callable
from dataclasses import dataclass
from typing import Any

log = logging.getLogger(__name__)


class StateStore(ABC):
    @abstractmethod
    def update[R](self, key: str, now: float, ttl: float,
                  step: Callable[[Any | None], tuple[Any, R]]) -> R:
        """Atomically apply `step` to the key's state and return its result.

        `step` receives None when the key is missing or expired. Its new state is
        stored with an expiry of now + ttl. Raises StoreError if the store fails.
        """

    @abstractmethod
    def purge_expired(self, now: float) -> int:
        """Delete every key whose expiry has passed. Returns how many went."""

    @abstractmethod
    def __len__(self) -> int:
        """Number of keys currently held, expired or not."""


@dataclass(slots=True)
class _Entry:
    state: Any
    expires_at: float


class InMemoryStore(StateStore):
    """A dict of key -> (state, expiry), guarded by one lock.

    One lock is the simplest correct choice: every update is O(1) or O(limit)
    and short. Lock striping is the next step if profiling ever says so.
    """

    def __init__(self) -> None:
        self._entries: dict[str, _Entry] = {}
        self._lock = threading.Lock()  # guards _entries and every state object in it

    def update[R](self, key: str, now: float, ttl: float,
                  step: Callable[[Any | None], tuple[Any, R]]) -> R:
        with self._lock:
            entry = self._entries.get(key)
            state = entry.state if entry is not None and entry.expires_at > now else None
            new_state, result = step(state)
            self._entries[key] = _Entry(new_state, now + ttl)
            return result

    def purge_expired(self, now: float) -> int:
        with self._lock:
            expired = [key for key, entry in self._entries.items() if entry.expires_at <= now]
            for key in expired:
                del self._entries[key]
        if expired:
            log.info("purged %d idle rate-limit keys", len(expired))
        return len(expired)

    def __len__(self) -> int:
        with self._lock:
            return len(self._entries)

What to notice. An expired entry reads as None, exactly as if it had already been purged. So correctness never depends on when the sweeper last ran. The sweep only frees memory. Redis behaves the same way: a key past its PEXPIRE is gone on read, whether or not the background expiry cycle has reached it yet. Also note that purge_expired logs after releasing the lock. Never do slow work, and logging can be slow, while every request thread waits on you.

        return rule

        return list(self._config.tiers.values())

"""The rate limiter: resolve the rule, run the algorithm in the store, decide.

It holds no mutable state of its own. All per-key state lives in the store,
which is what makes the same class work in one process or across a fleet.
"""
import logging
import threading

from .algorithms import RateLimitAlgorithm, default_algorithms
from .clock import Clock, MonotonicClock
from .config import LimitRule, RateLimiterConfig
from .decision import Decision
from .errors import (
    ConfigError,
    InvalidCostError,
    LimiterUnavailableError,
    StoreError,
    UnknownAlgorithmError,
)
from .rules import ClientKey, RuleBook
from .store import InMemoryStore, StateStore

log = logging.getLogger(__name__)


class RateLimiter:
    def __init__(
        self,
        config: RateLimiterConfig | None = None,
        *,
        store: StateStore | None = None,
        clock: Clock | None = None,
        algorithms: Mapping[str, RateLimitAlgorithm] | None = None,
    ) -> None:
        # `is None`, not `or`: an empty store defines __len__ == 0, so it is falsy.
        self._config = config if config is not None else RateLimiterConfig()
        self._store = store if store is not None else InMemoryStore()
        self._clock = clock if clock is not None else MonotonicClock()
        self._algorithms = dict(algorithms) if algorithms is not None else default_algorithms()
        self._rules = RuleBook(self._config)
        for rule in self._rules.rules():  # fail at startup, not on the first request
            if rule.algorithm not in self._algorithms:
                raise UnknownAlgorithmError(f"{rule.name}: no algorithm named {rule.algorithm!r}")

    def check(self, client: ClientKey, cost: int = 1) -> Decision:
        """Decide one request of `cost` units for `client`, and record it if allowed."""
        rule = self._rules.rule_for(client)
        if not 1 <= cost <= rule.capacity:
            raise InvalidCostError(f"cost must be between 1 and {rule.capacity}, got {cost}")
        algorithm = self._algorithms[rule.algorithm]
        now = self._clock.now()
        ttl = algorithm.idle_ttl(rule) + self._config.idle_grace_seconds
        try:
            decision = self._store.update(
                client.storage_key(rule), now, ttl,
                lambda state: algorithm.apply(state, rule, now, cost),
            )
        except StoreError as exc:
            return self._on_store_failure(rule, exc)
        if not decision.allowed:
            # DEBUG, not INFO: a client hammering a 429 would flood the logs.
            log.debug("denied %s:%s on %s, retry in %.3fs",
                      client.scope, client.value, rule.name, decision.retry_after)
        return decision

    @property
    def config(self) -> RateLimiterConfig:
        return self._config

    def sweep_idle(self) -> int:
        """Purge keys idle past their reset point. Returns how many were removed."""
        return self._store.purge_expired(self._clock.now())

    def _on_store_failure(self, rule: LimitRule, exc: StoreError) -> Decision:
        if self._config.fail_open:
            log.warning("rate-limit store failed, failing open for %s: %s", rule.name, exc)
            return Decision(True, rule.capacity, rule.capacity, 0.0, 0.0, degraded=True)
        log.error("rate-limit store failed, failing closed for %s: %s", rule.name, exc)
        raise LimiterUnavailableError(f"rate-limit store unavailable: {exc}") from exc


class IdleKeySweeper:
    """Background thread that calls limiter.sweep_idle() every interval.

    Use as a context manager, or call start() and stop() yourself.
    """

    def __init__(self, limiter: RateLimiter, interval_seconds: float | None = None) -> None:
        interval = limiter.config.sweep_interval_seconds if interval_seconds is None else interval_seconds
        if interval <= 0:
            raise ConfigError(f"sweep interval must be > 0, got {interval}")
        self._limiter = limiter
        self._interval = interval
        self._stop = threading.Event()
        self._thread: threading.Thread | None = None

    def start(self) -> None:
        if self._thread is not None:
            raise RuntimeError("sweeper already started")
        self._thread = threading.Thread(target=self._run, name="rate-limit-sweeper", daemon=True)
        self._thread.start()

    def stop(self) -> None:
        self._stop.set()
        if self._thread is not None:
            self._thread.join()

    def _run(self) -> None:
        while not self._stop.wait(self._interval):
            try:
                self._limiter.sweep_idle()
            except StoreError:
                log.exception("idle-key sweep failed; will retry next interval")

    def __enter__(self) -> "IdleKeySweeper":
        self.start()
        return self

    def __exit__(self, *exc_info: object) -> None:
        self.stop()

What to notice. Look at the comment above the constructor's defaults. The first draft of this file said store or InMemoryStore(), and a test caught it. StateStore defines __len__, so an empty store is falsy, and or quietly threw away the store the caller passed in. Use x if x is not None else default for any injected object that might define __len__ or __bool__.

Two more things. The constructor checks every rule's algorithm against the registry, so a typo in config fails at startup, not on the first request at 3 a.m. And now is read once per call, outside the store, then captured by the lambda. The algorithm, the expiry and the decision all agree on the same instant.

    def test_exactly_the_limit_passes_under_contention(self):

        for algorithm in Algorithm:
            with self.subTest(algorithm=algorithm):
                limiter, _ = make_limiter(LimitRule("t", limit, 60.0, algorithm))
                barrier = threading.Barrier(threads_count)
                results: list[bool] = []
                results_lock = threading.Lock()

                def hit():
                    barrier.wait()
                    allowed = limiter.check(USER).allowed
                    with results_lock:
                        results.append(allowed)

                for worker in workers:
                    worker.join()
                self.assertEqual(sum(results), limit)
                self.assertEqual(len(results), threads_count)

Honest limits. One lock serialises every key in the process. That is fine to tens of thousands of decisions per second, but it is a single point of contention. purge_expired scans every key under that lock, so a sweep over millions of keys pauses requests briefly. The sliding counter assumes requests in the previous window were spread evenly, so it can over- or under-admit slightly. 9. Common interview follow-ups

"Now there are twenty API servers behind a load balancer." The goalpost every rate-limiter interview reaches. Per-process dicts now allow 20× the limit. The fix is a shared store, almost always Redis, and the design change is a new StateStore implementation. The algorithm's step must still run atomically, and there are two ways to get that.

The first is optimistic: WATCH key, GET, run the Python apply, then MULTI / SET … PX ttl / EXEC, and retry if another server changed the key in between. It reuses the five algorithms unchanged, but hot keys retry a lot and every decision costs several round trips.

The second, and the production answer, is a Lua script per algorithm. Redis runs a script atomically, so the read, the arithmetic, the write and the expiry happen in one round trip with no retries. The price is that the step function now exists twice, once in Python and once in Lua, and the contract tests must run against both. For the token bucket:

-- KEYS[1] = bucket key; ARGV = capacity, rate_per_second, cost, ttl_ms
local t = redis.call('TIME')
local now = tonumber(t[1]) + tonumber(t[2]) / 1e6   -- server time: no app-clock skew
local capacity, rate = tonumber(ARGV[1]), tonumber(ARGV[2])
local cost, ttl_ms = tonumber(ARGV[3]), tonumber(ARGV[4])
local s = redis.call('HMGET', KEYS[1], 'level', 'ts')
local level = tonumber(s[1]) or capacity
local ts = tonumber(s[2]) or now
level = math.min(capacity, level + math.max(0, now - ts) * rate)
local allowed = 0
if level >= cost then level = level - cost; allowed = 1 end
redis.call('HSET', KEYS[1], 'level', level, 'ts', now)
redis.call('PEXPIRE', KEYS[1], ttl_ms)               -- idle_ttl + grace, as in memory
return {allowed, tostring(level)}

Three details are worth saying out loud. Use Redis's own TIME, not each app server's clock, or skew between servers refills buckets unevenly. Load the script once and call it by EVALSHA. And in Redis Cluster, keys touched by one script must share a hash slot, so wrap the client part of the key in braces (rl:{user:alice}:…) when one script touches several keys.

"Redis is down. What happens?" That is the fail_open flag. Most public APIs fail open: a limiter outage shouldn't become a full outage, so check returns a degraded allow and sends no rate-limit headers rather than invented ones. Payment and login endpoints often fail closed, because an attacker would love an unlimited window. The production upgrade is a third option: fall back to a local in-memory limiter with the limit divided by the number of servers. That is approximate, but bounded. In this design it is a StateStore that wraps a primary and a fallback.

"Apply a per-IP limit AND a per-user limit AND a global limit to the same request." Now one request is checked against several keys. The naive loop has a bug: if the per-IP check passes and consumes a token, then the per-user check denies, the IP was charged for a request that never ran. Two fixes. Either check all keys first with a read-only peek and commit only if all pass (two passes, and a small race between them in memory), or do all keys in one atomic unit: one lock acquisition in memory, one Lua script over several keys in Redis. The design change is a check_all(clients) method and a multi-key update on the store.

"Requests now cost LLM tokens, and you only know the count after the response." cost already handles a known cost. For an unknown one: reserve an estimate up front (max_tokens from the request), then reconcile once the real usage is known, refunding or charging the difference. That needs a second store operation, an adjust(key, delta), which is natural for token and leaky buckets and awkward for logs. Gateways usually pick a token bucket for that reason.

"A customer upgrades from free to pro mid-minute." The storage key includes the rule name, so their next request lands in a fresh, full pro bucket. That is generous by at most one bucket, and simple. If the business wants the used quota carried over, the rule book can map both tiers to a shared key and only the capacity changes. The token bucket handles that naturally, because min(capacity, level + refill) clamps to whatever the capacity is now.

"One lock for the whole process is a bottleneck." Stripe it: hash the key to one of N locks, each guarding its own dict. Requests for different keys stop contending, and the store interface doesn't change. Under the GIL, a single lock rarely shows up in profiles. On a free-threaded 3.13 build it will.

"Someone floods you with requests from a million spoofed IPs." Idle TTLs keep honest memory bounded, but a flood creates keys faster than they expire. Add a hard cap on tracked keys and, when it is hit, evict least-recently-used keys (an OrderedDict with move_to_end). Rate limit by /24 subnet as well as by IP. And put the cheapest check (a per-subnet fixed window) first.

"Should denied requests count against the limit?" Here they don't: no algorithm records a denied request. That is the forgiving choice: a client that backs off as told recovers on schedule. Counting denials punishes clients that ignore Retry-After. For abusive traffic that can be the right call, as a separate penalty rule rather than a change to the algorithms.
