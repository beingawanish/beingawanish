1. The problem

A BookMyShow-style service sells cinema seats. Cities have cinemas. Cinemas have screens. Each screen has a fixed seat layout, and every seat has a type — regular, premium, recliner — with its own price. A show is one movie on one screen at one time. Users search for shows, pick seats, pay, and sometimes cancel.

The hard part is not the catalog. It's the moment two people click seat B2 for the same show at the same instant. Exactly one of them may get it. And the winner doesn't own the seat yet: they get a hold, a ten-minute reservation while they pay. If they pay in time, the booking is confirmed. If they wander off, the hold expires and the seat goes back on sale. Payment runs through an outside gateway that can be slow, can decline, and can be called twice by an impatient double-click, so every charge carries an idempotency key. Cancelling a paid booking refunds money on a sliding scale: the closer to showtime, the less comes back.

So this chapter is really about three things. A race with one winner. A timer that gives things back. And money that must move exactly once.

2. Requirements

Clarifying questions to ask first (with the answers this chapter assumes)

  • How long is a hold? Ten minutes, from config. The interviewer will want it configurable, so it never appears as a literal.
  • Can a user hold some of the seats they asked for if others are taken? No. Seat selection is all-or-nothing. Half a family seated together is not a booking anyone wants.
  • Is the price fixed at hold time or at payment time? At hold time. The user saw a number; the hold locks it in.
  • Who calls payment, and is it synchronous? The service calls an injectable PaymentGateway. Assume synchronous for now. Async payment (UPI collect requests, webhooks) is a goalpost move in section 9.
  • What happens if the user's double-click sends "Pay" twice? One charge. The client sends an idempotency key, and the same key never charges twice.
  • What is the refund policy? Full refund 24 hours or more before showtime, half refund from 4 hours, nothing inside 4 hours. No cancellations once the show starts. All tiers come from config.
  • Single process or many? One process with threads for this round. Many app servers is a goalpost move, and you should say so before you are asked.
  • Is search on the same path as booking? No. Search is read-only and must never wait behind a seat lock.

Functional

  • Catalog: cities, cinemas, screens with seat layouts (rows of typed seats), movies, shows.
  • Search upcoming shows by city, optionally by movie and by date. Already-started shows never appear.
  • List a show's free seats with type and price.
  • Hold seats for a user: all-or-nothing, at most 10 seats, no duplicates, only seats that exist on that screen, only before showtime.
  • Confirm a hold by paying through the gateway, with a client-supplied idempotency key.
  • Holds expire after hold_seconds. An expired hold releases its seats and can never be confirmed.
  • Cancel a hold (free) or a confirmed booking (refund by tier). No cancellation after showtime.
  • Booking states follow one table: HELD → CONFIRMED / EXPIRED / CANCELLED, and CONFIRMED → CANCELLED. Nothing else.

Non-functional

  • Two users, same seat, same instant: exactly one wins. Under any thread interleaving.
  • Locking is per show. A rush on one blockbuster must not slow every other show.
  • No lock is held during a payment call.
  • Time is injectable. No datetime.now() in domain logic.
  • Money is Decimal, never float.
  • Typed exception hierarchy; no bare except. Stdlib only.

Where the interviewer will move the goalposts (answered in section 9): many app servers instead of one process; payment that completes later by webhook; a ticket drop where a million users arrive at 10:00:00; surge pricing; a "no single empty seat" rule.

5. Key design decisions

  1. A hold is a booking in state HELD, not a separate object. The seat map records "seat B2 belongs to booking BK1", whatever BK1's state. Confirming changes the booking's state, not the seat map. Expiring or cancelling changes the state and releases the seats. One owner per seat, one place to look.
  2. Every check-then-claim happens under the show's lock. "Are B1 and B2 free? Then they're mine" is the classic race. Two threads can both see "free" and both write "mine". SeatInventory hands out one RLock per show, and the service holds it across the check and the claim. Different shows get different locks, so a rush on one show never slows another.
  3. Claims are all-or-nothing. ShowSeatMap.claim checks every requested seat first and assigns only if all are free. A partial failure leaves nothing behind to clean up.
  4. Expiry is lazy, with a sweeper as backup. Every hold, read, and cancel first expires stale holds for that show, under the same lock. expire_holds() does the same sweep for a background job. No timer thread per hold. No timer that can fire mid-transaction.
  5. No lock during payment, so confirm runs in three phases. Check the hold under the lock. Charge with no lock held. Re-take the lock and commit only if the booking is still HELD. If the hold died while the money moved, refund automatically and say so. This is the decision interviewers probe hardest.
  6. Idempotency is enforced twice. The service binds each key to one booking, so a key reused for a different booking is rejected. The gateway returns the original receipt for a key it has seen, so a retry or a double-click never charges twice. Two layers, because the network can fail between them.
  7. The state machine is a table. ALLOWED_TRANSITIONS lists every legal move; Booking.transition_to refuses the rest. A new state (say PAYMENT_PENDING) is a new row, not a new if scattered across the service.
  8. Pricing and refunds are Strategies; numbers live in config. Surge pricing or a stricter refund window is a new class handed to the constructor. The service is never edited for a business-rule change.
  9. Search is a separate read path. ShowSearch reads the catalog and takes no show lock. Browsing never queues behind a seat race.

Patterns, and why each earns its place. State (as a transition table) for the booking life cycle: illegal moves fail loudly in one place. Strategy for pricing and refunds: the rules that change most are the cheapest to swap. Repository for the catalog and bookings: the dicts become tables later. Gateway (an adapter interface) for payment: the real provider and the fake are interchangeable. Per-key locking for seat inventory: as much concurrency as the problem allows, and no more.

    pass


class BookingNotFoundError(NotFoundError):
    pass

    """Someone else holds or owns at least one of the requested seats."""

        self.seat_ids = seat_ids

    """The seat hold ran out before the booking was confirmed."""

    """The show has started: no new holds, no cancellations."""

    """An idempotency key was reused for a different request."""

    """The payment gateway could not complete a charge or refund."""

    """The gateway refused the charge. Nothing was taken."""

Step 2 — Configuration: hold length, prices, refund tiers

Goal: one frozen place for every number the business can change, validated on construction.

Type movie_booking/config.py:

"""Configuration: seat types, prices, hold length, refund tiers.

Every number the business can change lives here, in frozen dataclasses,
so the booking logic never contains a literal price or a literal timeout.
"""
from dataclasses import dataclass, field
from datetime import timedelta
from decimal import Decimal
from enum import Enum

from .errors import InvalidConfigError


class SeatType(Enum):
    REGULAR = "regular"
    PREMIUM = "premium"
    RECLINER = "recliner"


@dataclass(frozen=True)
class RefundTier:
    """Cancel at least `min_hours_before_show` hours ahead, get `refund_percent` back."""

    min_hours_before_show: int
    refund_percent: int


@dataclass(frozen=True)
class BookingConfig:
    hold_seconds: int = 600
    max_seats_per_booking: int = 10
    currency: str = "INR"
    seat_prices: dict[SeatType, Decimal] = field(default_factory=lambda: {
        SeatType.REGULAR: Decimal("200.00"),
        SeatType.PREMIUM: Decimal("350.00"),
        SeatType.RECLINER: Decimal("600.00"),
    })
    # Most generous tier first. Anything later than the last tier refunds nothing.
    refund_tiers: tuple[RefundTier, ...] = (
        RefundTier(min_hours_before_show=24, refund_percent=100),
        RefundTier(min_hours_before_show=4, refund_percent=50),
    )

    def __post_init__(self) -> None:
        if self.hold_seconds <= 0:
            raise InvalidConfigError("hold_seconds must be positive")
        if self.max_seats_per_booking <= 0:
            raise InvalidConfigError("max_seats_per_booking must be positive")
        missing = [t.name for t in SeatType if t not in self.seat_prices]
        if missing:
            raise InvalidConfigError(f"no price for seat types: {missing}")
        if any(p < 0 for p in self.seat_prices.values()):
            raise InvalidConfigError("seat prices cannot be negative")
        hours = [t.min_hours_before_show for t in self.refund_tiers]
        if hours != sorted(hours, reverse=True) or len(set(hours)) != len(hours):
            raise InvalidConfigError("refund tiers must be strictly descending by hours")
        if any(not 0 <= t.refund_percent <= 100 for t in self.refund_tiers):
            raise InvalidConfigError("refund_percent must be within 0..100")

    @property
    def hold_duration(self) -> timedelta:
        return timedelta(seconds=self.hold_seconds)

What to notice. Prices are Decimal("200.00"), built from strings. Decimal(0.1) built from a float inherits the float's error; Decimal("0.1") does not. The refund tiers must be strictly descending by hours, because the refund policy walks them in order and takes the first that fits. __post_init__ enforces that, so a misordered config fails at startup instead of quietly refunding the wrong amount.

Step 3 — The clock

Goal: type the injectable clock. Hold expiry is pure time arithmetic, so the tests must own time.

Type movie_booking/clock.py:

"""Injectable clock. Hold expiry is pure time arithmetic, so tests must own time.

Domain code never calls datetime.now() directly. FixedClock lets a test jump
ten minutes forward in one line instead of sleeping for ten minutes.
"""
import threading
from abc import ABC, abstractmethod
from datetime import datetime, timedelta, timezone


class Clock(ABC):
    @abstractmethod
    def now(self) -> datetime:
        """Current time, always timezone-aware."""


class SystemClock(Clock):
    def now(self) -> datetime:
        return datetime.now(timezone.utc)


class FixedClock(Clock):
    """Test clock. Thread-safe, because the concurrency tests read it from many threads."""

    def __init__(self, start: datetime) -> None:
        if start.tzinfo is None:
            raise ValueError("FixedClock needs a timezone-aware datetime")
        self._now = start
        self._lock = threading.Lock()  # guards _now

    def now(self) -> datetime:
        with self._lock:
            return self._now

    def advance(self, delta: timedelta) -> None:
        with self._lock:
            self._now += delta

What to notice. This clock returns a datetime, not a date. Holds last minutes, so the car-rental chapter's day-level clock is too coarse here. FixedClock also takes a lock, unlike the earlier chapters' clocks. The concurrency tests read it from twenty threads at once, and a test clock that races is a test that lies.

Step 4 — The models, and the state machine as a table

Goal: type the catalog objects and the Booking, which owns its own transitions.

Type movie_booking/models.py:

"""Domain models: the catalog (cinema, screen, seat, movie, show) and the Booking.

Catalog objects are frozen: a screen's layout does not change under a live show.
Booking is the one mutable model, and it guards its own state machine.
"""
from collections.abc import Sequence
from dataclasses import dataclass, field
from datetime import datetime
from decimal import Decimal
from enum import Enum

from .config import SeatType
from .errors import InvalidRequestError, InvalidTransitionError


@dataclass(frozen=True)
class Cinema:
    cinema_id: str
    name: str
    city: str


@dataclass(frozen=True)
class Seat:
    seat_id: str
    seat_type: SeatType


@dataclass(frozen=True)
class Screen:
    screen_id: str
    cinema_id: str
    name: str
    seats: tuple[Seat, ...]
    _index: dict[str, Seat] = field(init=False, repr=False, compare=False)

    def __post_init__(self) -> None:
        if not self.seats:
            raise InvalidRequestError(f"screen {self.screen_id} has no seats")
        index = {s.seat_id: s for s in self.seats}
        if len(index) != len(self.seats):
            raise InvalidRequestError(f"screen {self.screen_id} has duplicate seat ids")
        object.__setattr__(self, "_index", index)

    def seat(self, seat_id: str) -> Seat | None:
        return self._index.get(seat_id)

    @classmethod
    def from_rows(
        cls, screen_id: str, cinema_id: str, name: str,
        rows: Sequence[tuple[str, int, SeatType]],
    ) -> "Screen":
        """Build a layout from (row letter, seats in row, seat type) triples."""
        seats = tuple(
            Seat(f"{row}{n}", seat_type)
            for row, count, seat_type in rows
            for n in range(1, count + 1)
        )
        return cls(screen_id, cinema_id, name, seats)


@dataclass(frozen=True)
class Movie:
    movie_id: str
    title: str
    duration_minutes: int


@dataclass(frozen=True)
class Show:
    show_id: str
    movie_id: str
    screen_id: str
    starts_at: datetime

    def __post_init__(self) -> None:
        if self.starts_at.tzinfo is None:
            raise InvalidRequestError("show times must be timezone-aware")


class BookingStatus(Enum):
    HELD = "held"
    CONFIRMED = "confirmed"
    EXPIRED = "expired"
    CANCELLED = "cancelled"


# The whole state machine, in one table. EXPIRED and CANCELLED are terminal.
ALLOWED_TRANSITIONS: dict[BookingStatus, frozenset[BookingStatus]] = {
    BookingStatus.HELD: frozenset({
        BookingStatus.CONFIRMED, BookingStatus.EXPIRED, BookingStatus.CANCELLED,
    }),
    BookingStatus.CONFIRMED: frozenset({BookingStatus.CANCELLED}),
    BookingStatus.EXPIRED: frozenset(),
    BookingStatus.CANCELLED: frozenset(),
}


@dataclass
class Booking:
    """One user's seats for one show.

    Mutated only by BookingService while it holds that show's lock.
    """

    booking_id: str
    show_id: str
    user_id: str
    seat_ids: tuple[str, ...]
    amount: Decimal
    held_until: datetime
    status: BookingStatus = BookingStatus.HELD
    payment_id: str | None = None
    idempotency_key: str | None = None
    refund_amount: Decimal = Decimal("0.00")

    def transition_to(self, new_status: BookingStatus) -> None:
        if new_status not in ALLOWED_TRANSITIONS[self.status]:
            raise InvalidTransitionError(
                f"booking {self.booking_id}: {self.status.name} -> {new_status.name} not allowed"
            )
        self.status = new_status

    def is_hold_expired(self, now: datetime) -> bool:
        return self.status is BookingStatus.HELD and now >= self.held_until

What to notice. Read ALLOWED_TRANSITIONS once, slowly. It is the state diagram from section 4. transition_to is the only way the status changes, so an illegal move cannot happen silently anywhere in the code. Also look at is_hold_expired: it uses >=. At exactly held_until the hold is over. Pick a boundary, write it down, and test it, or two engineers will pick two different ones.

Type movie_booking/repositories.py:

"""Repositories: the catalog (read-mostly) and the bookings (write-heavy).

Two interfaces because they change for different reasons and would live in
different stores in production: the catalog in a cached SQL table, bookings
in the transactional store.
"""
import threading
from abc import ABC, abstractmethod

from .errors import BookingNotFoundError, NotFoundError, ShowNotFoundError
from .models import Booking, Cinema, Movie, Screen, Show


class CatalogRepository(ABC):
    @abstractmethod
    def add_cinema(self, cinema: Cinema) -> None: ...

    @abstractmethod
    def add_screen(self, screen: Screen) -> None: ...

    @abstractmethod
    def add_movie(self, movie: Movie) -> None: ...

    @abstractmethod
    def add_show(self, show: Show) -> None: ...

    @abstractmethod
    def get_cinema(self, cinema_id: str) -> Cinema: ...

    @abstractmethod
    def get_screen(self, screen_id: str) -> Screen: ...

    @abstractmethod
    def get_movie(self, movie_id: str) -> Movie: ...

    @abstractmethod
    def get_show(self, show_id: str) -> Show: ...

    @abstractmethod
    def all_shows(self) -> list[Show]: ...


class InMemoryCatalog(CatalogRepository):
    def __init__(self) -> None:
        self._cinemas: dict[str, Cinema] = {}
        self._screens: dict[str, Screen] = {}
        self._movies: dict[str, Movie] = {}
        self._shows: dict[str, Show] = {}
        self._lock = threading.Lock()  # guards all four dicts

    def add_cinema(self, cinema: Cinema) -> None:
        with self._lock:
            self._cinemas[cinema.cinema_id] = cinema

    def add_screen(self, screen: Screen) -> None:
        with self._lock:
            if screen.cinema_id not in self._cinemas:
                raise NotFoundError(f"unknown cinema {screen.cinema_id}")
            self._screens[screen.screen_id] = screen

    def add_movie(self, movie: Movie) -> None:
        with self._lock:
            self._movies[movie.movie_id] = movie

    def add_show(self, show: Show) -> None:
        with self._lock:
            if show.screen_id not in self._screens:
                raise NotFoundError(f"unknown screen {show.screen_id}")
            if show.movie_id not in self._movies:
                raise NotFoundError(f"unknown movie {show.movie_id}")
            self._shows[show.show_id] = show

    def get_cinema(self, cinema_id: str) -> Cinema:
        with self._lock:
            if cinema_id not in self._cinemas:
                raise NotFoundError(f"unknown cinema {cinema_id}")
            return self._cinemas[cinema_id]

    def get_screen(self, screen_id: str) -> Screen:
        with self._lock:
            if screen_id not in self._screens:
                raise NotFoundError(f"unknown screen {screen_id}")
            return self._screens[screen_id]

    def get_movie(self, movie_id: str) -> Movie:
        with self._lock:
            if movie_id not in self._movies:
                raise NotFoundError(f"unknown movie {movie_id}")
            return self._movies[movie_id]

    def get_show(self, show_id: str) -> Show:
        with self._lock:
            if show_id not in self._shows:
                raise ShowNotFoundError(f"unknown show {show_id}")
            return self._shows[show_id]

    def all_shows(self) -> list[Show]:
        with self._lock:
            return list(self._shows.values())


class BookingRepository(ABC):
    @abstractmethod
    def add(self, booking: Booking) -> None: ...

    @abstractmethod
    def get(self, booking_id: str) -> Booking: ...

    @abstractmethod
    def for_show(self, show_id: str) -> list[Booking]: ...


class InMemoryBookingRepository(BookingRepository):
    def __init__(self) -> None:
        self._bookings: dict[str, Booking] = {}
        self._by_show: dict[str, list[str]] = {}
        self._lock = threading.Lock()  # guards both dicts

    def add(self, booking: Booking) -> None:
        with self._lock:
            self._bookings[booking.booking_id] = booking
            self._by_show.setdefault(booking.show_id, []).append(booking.booking_id)

    def get(self, booking_id: str) -> Booking:
        with self._lock:
            if booking_id not in self._bookings:
                raise BookingNotFoundError(f"unknown booking {booking_id}")
            return self._bookings[booking_id]

    def for_show(self, show_id: str) -> list[Booking]:
        with self._lock:
            return [self._bookings[b] for b in self._by_show.get(show_id, [])]

What to notice. add_show refuses a show whose screen or movie doesn't exist. Referential integrity is checked at the boundary, the way a foreign key would. for_show keeps a per-show index so the expiry sweep doesn't scan every booking in the system. Each repository's lock guards only its own dicts; it says nothing about seats. That job belongs to the next file.

Step 6 — The seat inventory: one lock per show

Goal: type the heart of the chapter. ShowSeatMap knows who owns each seat. SeatInventory gives each show its own lock.

Type movie_booking/seat_inventory.py:

"""Seat inventory: who owns which seat of a show, plus one lock per show.

This is the heart of the chapter. Two users click the same seat at the same
instant; exactly one claim may succeed. The rule is enforced in two layers:

* ShowSeatMap.claim is all-or-nothing: it checks every seat, then assigns them.
* SeatInventory hands out one RLock per show, and BookingService performs
  every check-then-claim while holding it. Different shows never contend.
"""
import threading
from collections.abc import Iterable
from dataclasses import dataclass

from .errors import SeatUnavailableError
from .repositories import CatalogRepository


class ShowSeatMap:
    """Seat ownership for one show: seat_id -> booking_id, or None when free.

    Not thread-safe by itself. Callers hold the show's lock.
    """

    def __init__(self, show_id: str, seat_ids: Iterable[str]) -> None:
        self._show_id = show_id
        self._owner: dict[str, str | None] = {seat_id: None for seat_id in seat_ids}

    def owner(self, seat_id: str) -> str | None:
        return self._owner[seat_id]

    def free_seat_ids(self) -> list[str]:
        return [s for s, owner in self._owner.items() if owner is None]

    def claim(self, seat_ids: Iterable[str], booking_id: str) -> None:
        wanted = list(seat_ids)
        taken = [s for s in wanted if self._owner[s] is not None]
        if taken:
            raise SeatUnavailableError(self._show_id, taken)
        for seat_id in wanted:
            self._owner[seat_id] = booking_id

    def release(self, seat_ids: Iterable[str], booking_id: str) -> None:
        """Free only the seats this booking actually owns."""
        for seat_id in seat_ids:
            if self._owner.get(seat_id) == booking_id:
                self._owner[seat_id] = None


@dataclass
class ShowState:
    lock: threading.RLock
    seats: ShowSeatMap


class SeatInventory:
    """Creates each show's state on first use and hands back the same one after."""

    def __init__(self, catalog: CatalogRepository) -> None:
        self._catalog = catalog
        self._states: dict[str, ShowState] = {}
        # Guards _states only. Never held while a show lock is held.
        self._registry_lock = threading.Lock()

    def for_show(self, show_id: str) -> ShowState:
        with self._registry_lock:
            state = self._states.get(show_id)
            if state is None:
                show = self._catalog.get_show(show_id)
                screen = self._catalog.get_screen(show.screen_id)
                state = ShowState(
                    lock=threading.RLock(),
                    seats=ShowSeatMap(show_id, (s.seat_id for s in screen.seats)),
                )
                self._states[show_id] = state
            return state

What to notice. ShowSeatMap has no lock of its own, on purpose. Its docstring says the caller holds the show's lock. Putting a second lock inside would invite the very bug we're avoiding: a "check" under one lock and a "claim" under another. release frees only seats this booking owns, so a late release from an old booking can never free a seat someone else now holds. And _registry_lock is held only long enough to find or create a ShowState. It is never held while a show lock is taken, so the two locks cannot deadlock.

CENT = Decimal("0.01")
ONE_HOUR = timedelta(hours=1)


class PricingStrategy(ABC):
    @abstractmethod
    def price(self, show: Show, seat: Seat) -> Decimal:
        """Price of one seat for one show."""


class SeatTypePricing(PricingStrategy):
    """Flat price per seat type, straight from the config."""

    def __init__(self, config: BookingConfig) -> None:
        self._config = config

    def price(self, show: Show, seat: Seat) -> Decimal:
        return self._config.seat_prices[seat.seat_type]


class RefundPolicy(ABC):
    @abstractmethod
    def refund_for(self, booking: Booking, show: Show, now: datetime) -> Decimal:
        """How much of booking.amount goes back if cancelled at `now`."""


class TieredRefundPolicy(RefundPolicy):
    """Walks the config's tiers, most generous first; the first one that fits wins."""

    def __init__(self, config: BookingConfig) -> None:
        self._tiers = config.refund_tiers

    def refund_for(self, booking: Booking, show: Show, now: datetime) -> Decimal:
        hours_before = (show.starts_at - now) / ONE_HOUR
        for tier in self._tiers:
            if hours_before >= tier.min_hours_before_show:
                share = booking.amount * tier.refund_percent / Decimal(100)
                return share.quantize(CENT, rounding=ROUND_HALF_UP)
        return Decimal("0.00")

What to notice. (show.starts_at - now) / ONE_HOUR divides a timedelta by a timedelta and gives a float number of hours. No manual seconds arithmetic. The refund is rounded once, with ROUND_HALF_UP, at the point it is computed. The tier edges are inclusive: exactly 24 hours before still earns the full refund.

Step 8 — The payment gateway seam

"""Payment gateway seam, plus an in-memory fake with real idempotency semantics.

Idempotency contract (the same one real gateways publish): a charge with a
key the gateway has already seen returns the original receipt and moves no
money. Same key with a different amount is a client bug and is rejected.
"""
import itertools
import logging
import threading
from abc import ABC, abstractmethod
from collections.abc import Callable, Iterable
from dataclasses import dataclass
from decimal import Decimal

from .errors import IdempotencyConflictError, PaymentDeclinedError

log = logging.getLogger(__name__)


@dataclass(frozen=True)
class PaymentReceipt:
    payment_id: str
    idempotency_key: str
    amount: Decimal


@dataclass(frozen=True)
class RefundReceipt:
    refund_id: str
    payment_id: str
    amount: Decimal


class PaymentGateway(ABC):
    @abstractmethod
    def charge(self, *, idempotency_key: str, user_id: str, amount: Decimal) -> PaymentReceipt:
        """Take money. Raises PaymentDeclinedError if refused."""

    @abstractmethod
    def refund(self, *, idempotency_key: str, payment_id: str, amount: Decimal) -> RefundReceipt:
        """Give money back against an earlier charge."""


class FakePaymentGateway(PaymentGateway):
    """Test double. Ids are sequential so demo output is stable.

    `after_charge` runs after a new charge, outside the lock. Tests use it to
    simulate the clock moving while a slow payment is in flight.
    """

    def __init__(
        self,
        decline_users: Iterable[str] = (),
        after_charge: Callable[[], None] | None = None,
    ) -> None:
        self.decline_users: set[str] = set(decline_users)  # tests may edit
        self.after_charge = after_charge
        self._charges: dict[str, PaymentReceipt] = {}
        self._refunds: dict[str, RefundReceipt] = {}
        self._ids = itertools.count(1)
        self._lock = threading.Lock()  # guards _charges, _refunds, _ids

    def charge(self, *, idempotency_key: str, user_id: str, amount: Decimal) -> PaymentReceipt:
        with self._lock:
            seen = self._charges.get(idempotency_key)
            if seen is not None:
                if seen.amount != amount:
                    raise IdempotencyConflictError(
                        f"key {idempotency_key} already used for {seen.amount}"
                    )
                log.info("charge replayed for key %s", idempotency_key)
                return seen
            if user_id in self.decline_users:
                raise PaymentDeclinedError(f"card declined for {user_id}")
            receipt = PaymentReceipt(f"pay-{next(self._ids)}", idempotency_key, amount)
            self._charges[idempotency_key] = receipt
        log.info("charged %s as %s", amount, receipt.payment_id)
        if self.after_charge is not None:
            self.after_charge()
        return receipt

    def refund(self, *, idempotency_key: str, payment_id: str, amount: Decimal) -> RefundReceipt:
        with self._lock:
            seen = self._refunds.get(idempotency_key)
            if seen is not None:
                return seen
            receipt = RefundReceipt(f"ref-{next(self._ids)}", payment_id, amount)
            self._refunds[idempotency_key] = receipt
        log.info("refunded %s against %s", amount, payment_id)
        return receipt

    @property
    def charge_count(self) -> int:
        with self._lock:
            return len(self._charges)

    @property
    def total_charged(self) -> Decimal:
        with self._lock:
            return sum((r.amount for r in self._charges.values()), Decimal("0.00"))

    @property
    def total_refunded(self) -> Decimal:
        with self._lock:
            return sum((r.amount for r in self._refunds.values()), Decimal("0.00"))

What to notice. The fake is not a dumb stub. It implements the idempotency contract the way real gateways publish it: same key, same receipt, no second charge; same key with a different amount, rejected. The after_charge hook runs outside the lock and lets a test move the clock while a payment is "in flight". That is how section 7 proves the refund-on-lost-hold path without sleeping.

class ShowSearch:
    def __init__(self, catalog: CatalogRepository, clock: Clock) -> None:
        self._catalog = catalog
        self._clock = clock

    def find(
        self, city: str, *, movie_id: str | None = None, on_date: date | None = None,
    ) -> list[ShowListing]:
        """Upcoming shows in a city, soonest first. Dates are the show's local date."""
        if not city.strip():
            raise InvalidRequestError("city is required")
        now = self._clock.now()
        listings = []
        for show in self._catalog.all_shows():
            if show.starts_at <= now:
                continue
            if movie_id is not None and show.movie_id != movie_id:
                continue
            if on_date is not None and show.starts_at.date() != on_date:
                continue
            screen = self._catalog.get_screen(show.screen_id)
            cinema = self._catalog.get_cinema(screen.cinema_id)
            if cinema.city.casefold() != city.strip().casefold():
                continue
            movie = self._catalog.get_movie(show.movie_id)
            listings.append(ShowListing(show, movie, cinema, screen))
        return sorted(listings, key=lambda listing: listing.show.starts_at)

Step 10 — The service: hold, confirm, cancel, expire

Goal: type BookingService. It owns every lock decision, so its module docstring states the rules before any code does.

Type movie_booking/service.py:

"""BookingService: hold seats, confirm with payment, cancel with refund, expire holds.

Locking rules, stated once:

* Every read-check-write on a show's seats or bookings happens under that
  show's RLock (SeatInventory.for_show(...).lock). Shows never block each other.
* No lock is held while the payment gateway is called. A slow gateway must not
  freeze a whole show's seat map. confirm() therefore runs in three phases:
  check under the lock, charge outside it, re-check and commit under it again.
* _keys_lock guards only the idempotency-key map and is never held while
  waiting for any other lock.
"""
import logging
import threading
import uuid
from collections.abc import Callable, Sequence
from dataclasses import dataclass
from decimal import Decimal

from .clock import Clock, SystemClock
from .config import BookingConfig, SeatType
from .errors import (
    HoldExpiredError,
    IdempotencyConflictError,
    InvalidRequestError,
    InvalidSeatSelectionError,
    InvalidTransitionError,
    ShowClosedError,
)
from .models import Booking, BookingStatus, Screen, Seat, Show
from .payments import PaymentGateway
from .policies import PricingStrategy, RefundPolicy, SeatTypePricing, TieredRefundPolicy
from .repositories import BookingRepository, CatalogRepository
from .seat_inventory import SeatInventory, ShowState

log = logging.getLogger(__name__)


def _random_id() -> str:
    return uuid.uuid4().hex[:8]


@dataclass(frozen=True)
class SeatOffer:
    seat_id: str
    seat_type: SeatType
    price: Decimal


class BookingService:
    def __init__(
        self,
        catalog: CatalogRepository,
        bookings: BookingRepository,
        gateway: PaymentGateway,
        *,
        config: BookingConfig | None = None,
        clock: Clock | None = None,
        pricing: PricingStrategy | None = None,
        refund_policy: RefundPolicy | None = None,
        inventory: SeatInventory | None = None,
        id_factory: Callable[[], str] = _random_id,
    ) -> None:
        self._catalog = catalog
        self._bookings = bookings
        self._gateway = gateway
        self._config = config or BookingConfig()
        self._clock = clock or SystemClock()
        self._pricing = pricing or SeatTypePricing(self._config)
        self._refunds = refund_policy or TieredRefundPolicy(self._config)
        self._inventory = inventory or SeatInventory(catalog)
        self._new_id = id_factory
        self._keys: dict[str, str] = {}  # idempotency key -> booking_id
        self._keys_lock = threading.Lock()  # guards _keys only

    # ---- reads -------------------------------------------------------

    def available_seats(self, show_id: str) -> list[SeatOffer]:
        show = self._catalog.get_show(show_id)
        screen = self._catalog.get_screen(show.screen_id)
        state = self._inventory.for_show(show_id)
        with state.lock:
            self._expire_locked(show_id, state)
            free = state.seats.free_seat_ids()
        return [
            SeatOffer(seat.seat_id, seat.seat_type, self._pricing.price(show, seat))
            for seat in (screen.seat(s) for s in free) if seat is not None
        ]

    # ---- hold --------------------------------------------------------

    def hold_seats(self, show_id: str, user_id: str, seat_ids: Sequence[str]) -> Booking:
        if not user_id.strip():
            raise InvalidRequestError("user_id is required")
        show = self._catalog.get_show(show_id)
        screen = self._catalog.get_screen(show.screen_id)
        seats = self._validate_selection(screen, seat_ids)
        amount = sum((self._pricing.price(show, s) for s in seats), Decimal("0.00"))
        state = self._inventory.for_show(show_id)
        with state.lock:
            now = self._clock.now()
            if now >= show.starts_at:
                raise ShowClosedError(f"show {show_id} has already started")
            self._expire_locked(show_id, state)
            booking = Booking(
                booking_id=self._new_id(),
                show_id=show_id,
                user_id=user_id,
                seat_ids=tuple(seat_ids),
                amount=amount,
                held_until=now + self._config.hold_duration,
            )
            state.seats.claim(booking.seat_ids, booking.booking_id)
            self._bookings.add(booking)
        log.info("held %s for %s on %s (booking %s)",
                 ",".join(booking.seat_ids), user_id, show_id, booking.booking_id)
        return booking

    # ---- confirm -----------------------------------------------------

    def confirm(self, booking_id: str, idempotency_key: str) -> Booking:
        if not idempotency_key.strip():
            raise InvalidRequestError("idempotency_key is required")
        booking = self._bookings.get(booking_id)
        self._bind_key(idempotency_key, booking_id)
        state = self._inventory.for_show(booking.show_id)

        # Phase 1, under the lock: is there still a live hold to pay for?
        with state.lock:
            if booking.status is BookingStatus.CONFIRMED:
                if booking.idempotency_key == idempotency_key:
                    return booking  # a retry of a confirm that already worked
                raise InvalidTransitionError(f"booking {booking_id} is already confirmed")
            if booking.is_hold_expired(self._clock.now()):
                self._expire_one_locked(booking, state)
            if booking.status is BookingStatus.EXPIRED:
                raise HoldExpiredError(f"hold on booking {booking_id} has expired")
            if booking.status is not BookingStatus.HELD:
                raise InvalidTransitionError(
                    f"booking {booking_id} is {booking.status.name}, cannot confirm"
                )
            amount, user_id = booking.amount, booking.user_id

        # Phase 2, no lock: the slow network call. Declines propagate; the hold survives.
        receipt = self._gateway.charge(
            idempotency_key=idempotency_key, user_id=user_id, amount=amount,
        )

        # Phase 3, under the lock: commit only if the seats are still ours.
        with state.lock:
            if booking.status is BookingStatus.HELD:
                booking.transition_to(BookingStatus.CONFIRMED)
                booking.payment_id = receipt.payment_id
                booking.idempotency_key = idempotency_key
                log.info("confirmed booking %s with %s", booking_id, receipt.payment_id)
                return booking
            if booking.payment_id == receipt.payment_id:
                return booking  # a concurrent retry with the same key got here first
            lost_to = booking.status

        # The hold ended while we were charging. Give the money back, then say so.
        self._gateway.refund(
            idempotency_key=f"auto-refund-{idempotency_key}",
            payment_id=receipt.payment_id, amount=receipt.amount,
        )
        log.warning("booking %s became %s during payment; refunded %s",
                    booking_id, lost_to.name, receipt.payment_id)
        error = InvalidTransitionError if lost_to is BookingStatus.CONFIRMED else HoldExpiredError
        raise error(f"booking {booking_id} became {lost_to.name} during payment; charge refunded")

    # ---- cancel ------------------------------------------------------

    def cancel(self, booking_id: str) -> Booking:
        booking = self._bookings.get(booking_id)
        show = self._catalog.get_show(booking.show_id)
        state = self._inventory.for_show(booking.show_id)
        with state.lock:
            now = self._clock.now()
            self._expire_locked(booking.show_id, state)
            was_confirmed = booking.status is BookingStatus.CONFIRMED
            if was_confirmed and now >= show.starts_at:
                raise ShowClosedError(f"show {show.show_id} has started; cannot cancel")
            refund = (self._refunds.refund_for(booking, show, now)
                      if was_confirmed else Decimal("0.00"))
            booking.transition_to(BookingStatus.CANCELLED)  # raises for EXPIRED/CANCELLED
            booking.refund_amount = refund
            state.seats.release(booking.seat_ids, booking.booking_id)
            payment_id = booking.payment_id
        if was_confirmed and refund > 0 and payment_id is not None:
            self._gateway.refund(
                idempotency_key=f"refund-{booking_id}", payment_id=payment_id, amount=refund,
            )
        log.info("cancelled booking %s, refund %s", booking_id, refund)
        return booking

    # ---- expiry ------------------------------------------------------

    def expire_holds(self, show_id: str | None = None) -> int:
        """Sweep expired holds. A background job calls this; reads call it lazily too."""
        show_ids = [show_id] if show_id else [s.show_id for s in self._catalog.all_shows()]
        expired = 0
        for sid in show_ids:
            state = self._inventory.for_show(sid)
            with state.lock:
                expired += self._expire_locked(sid, state)
        return expired

    # ---- helpers (callers hold the show lock where the name says _locked) --

    def _expire_locked(self, show_id: str, state: ShowState) -> int:
        now = self._clock.now()
        count = 0
        for booking in self._bookings.for_show(show_id):
            if booking.is_hold_expired(now):
                self._expire_one_locked(booking, state)
                count += 1
        return count

    def _expire_one_locked(self, booking: Booking, state: ShowState) -> None:
        booking.transition_to(BookingStatus.EXPIRED)
        state.seats.release(booking.seat_ids, booking.booking_id)
        log.info("hold expired: booking %s released %s",
                 booking.booking_id, ",".join(booking.seat_ids))

    def _bind_key(self, key: str, booking_id: str) -> None:
        with self._keys_lock:
            bound = self._keys.setdefault(key, booking_id)
        if bound != booking_id:
            raise IdempotencyConflictError(f"key {key} already used for booking {bound}")

    def _validate_selection(self, screen: Screen, seat_ids: Sequence[str]) -> list[Seat]:
        if isinstance(seat_ids, str) or not seat_ids:
            raise InvalidSeatSelectionError("pick at least one seat, as a list of ids")
        if len(set(seat_ids)) != len(seat_ids):
            raise InvalidSeatSelectionError(f"duplicate seats in {list(seat_ids)}")
        limit = self._config.max_seats_per_booking
        if len(seat_ids) > limit:
            raise InvalidSeatSelectionError(f"at most {limit} seats per booking")
        seats = [screen.seat(s) for s in seat_ids]
        unknown = [s for s, seat in zip(seat_ids, seats) if seat is None]
        if unknown:
            raise InvalidSeatSelectionError(f"no such seats on {screen.name}: {unknown}")
        return [s for s in seats if s is not None]

What to notice. Start with hold_seats. Validation and pricing run before the lock. They only read immutable catalog data, so there's no reason to make other users wait for them. Inside the lock: the showtime check, the expiry sweep, the claim, the store. In that order, so a stale hold is cleared before anyone is told "taken".

Then confirm, which is the method to rehearse out loud. Phase 1 checks the hold under the lock and copies the amount out. Phase 2 calls the gateway with no lock held; a ten-second payment stalls nobody. Phase 3 re-takes the lock and asks one question: is this booking still HELD? If yes, confirm. If a concurrent retry with the same key already confirmed it, return it. Otherwise the hold ended while the money moved, so refund with a derived key and raise. A declined card raises in phase 2 and leaves the hold untouched, so the user can retry with another card before the timer runs out.

One small honesty: the booking id is drawn before the claim. A request that loses the race still burns an id. With random ids that costs nothing, but it's why the demo below skips from BK1 to BK3.

    def test_many_users_one_seat_exactly_one_winner(self):
        service, _, _ = make_service()

        wins, losses = [], []

        def attempt(user: str) -> None:
            barrier.wait()
            try:

            results.append(service.confirm(b.booking_id, "same-key").status)

            t.join()

9. Common interview follow-ups

Why not hold the show lock during the payment call? It would be simpler. Simpler and much worse. A gateway call can take seconds. Under the lock, every other user of that show — browsing seats, holding, cancelling — waits behind one person's card. The three-phase confirm keeps the lock to microseconds. The price is one extra case: the hold can die mid-payment. We handle it by refunding automatically, and that case has its own test.

Goalpost: "Now run it on six app servers behind a load balancer." An in-process RLock means nothing across machines. Move the claim into the database as one conditional statement: UPDATE show_seats SET booking_id = :b, held_until = :t WHERE show_id = :s AND seat_id IN (...) AND (booking_id IS NULL OR held_until <= now()), then check that the affected row count equals the number of seats requested, and roll back if not. The database becomes the atomic check-then-act. Add a unique constraint on (show_id, seat_id) in the tickets table as a final guard. A Redis SET seat:{show}:{seat} {booking} NX PX 600000 per seat works too, and its TTL is the hold expiry. The design change is small: ShowSeatMap becomes an interface with an in-memory and a SQL implementation, and SeatInventory's lock becomes the database transaction.

Goalpost: "Payment is UPI. The money arrives by webhook, maybe two minutes later." Add a PAYMENT_PENDING state between HELD and CONFIRMED: one new row in ALLOWED_TRANSITIONS. Entering it extends the hold, and the sweeper must not expire a pending booking until the gateway's own timeout passes. The webhook handler is idempotent on the gateway's event id, because providers deliver webhooks at least once. A reconciliation job asks the gateway about anything stuck in PAYMENT_PENDING. The phase-3 logic stays the same: if the booking is no longer ours when the money lands, refund.

Goalpost: "A blockbuster opens at 10:00:00 and a million people arrive in one second." Per-show locking now hurts. Every request hits one lock. Put a virtual waiting room in front: admit users in batches with a signed token, so the seat map sees a steady flow instead of a stampede. Cap holds per user (one live hold per user per show) to stop scalpers hoarding seats with ten browser tabs. Shorten hold_seconds for the event through config. You don't need code for that one.

Goalpost: "Prices should surge as the show fills up." A new OccupancyPricing(PricingStrategy) that reads the show's occupancy and multiplies. The service is untouched. The design already locks the price at hold time (Booking.amount), so the user pays what they saw, even if the next seat costs more.

Goalpost: "Don't let anyone leave a single empty seat between two booked ones." That's a seat-selection rule, so it belongs in validation, not in the seat map. Extract _validate_selection into a list of SelectionRule objects. The orphan-seat rule needs the current seat map, so it runs inside the lock, after the expiry sweep and before the claim.

How does idempotency survive a crash between "charged" and "confirmed"? The client retries with the same key. Phase 1 sees HELD, phase 2 asks the gateway, and the gateway returns the original receipt instead of charging again. Phase 3 confirms. That's why both layers exist: the service-side key map alone couldn't know the gateway had already taken the money.

Why is expiry lazy instead of a timer per hold? A timer per hold is a thread or scheduled callback per click. It can fire in the middle of a confirm, and it is lost if the process restarts. Lazy expiry runs under the show lock at the moment it matters, so it can't race with confirm. The sweeper only cleans up shows nobody is looking at.
