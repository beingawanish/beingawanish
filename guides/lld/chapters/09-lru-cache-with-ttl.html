Chapter 9: LRU Cache with TTL

Type every file in order. Run each checkpoint before moving on. Checkpoints run from the code/ folder (the one holding cache/). The full suite runs from the guide root (the folder holding code/ and tests/). Python 3.13, stdlib only.

Every backend has a cache somewhere, and most of them were written in a hurry. This chapter builds one properly. Reads and writes run in constant time. The eviction policy is a choice, entries expire, and capacity comes in two kinds. There are numbers for a dashboard. And a loader keeps a thousand simultaneous misses from turning into a thousand database calls. It is the most-asked LLD problem there is. It is also the one where interviewers dig deepest, because the first ten minutes look easy and the next forty do not.

1. The problem

Build an in-process key-value cache for a service. It holds a bounded number of entries. When it is full, an eviction policy decides what leaves: least recently used by default, with least frequently used and first-in-first-out available as swaps. Each entry can carry its own time-to-live. Expired entries must never be served, and they should not linger in memory forever either. Capacity can be measured in entries, in size units (bytes, say), or both. Operators want hit, miss and eviction counts. Other code wants to hear when something leaves the cache. Many threads share one instance. And when a hot key expires, the cache must not let every waiting request hit the database at once.

2. Requirements

Clarifying questions to ask first (with the answers this chapter assumes)

  • How big, and measured how? Up to max_entries entries, and optionally up to max_size size units, where a pluggable sizer says how big each value is. Both limits apply when both are set.
  • Which eviction policy? LRU by default. LFU and FIFO must be drop-in swaps. "Can you make it pluggable?" is coming either way, so design for it now.
  • What does a miss return? A default value, never an exception. None must be a legitimate cached value, so the cache needs a sentinel.
  • TTL per cache or per entry? Both: a default in config, overridable per put.
  • Must an expired entry be removed the instant it expires? No. It must never be returned. Removal can be lazy (on the next read) with an optional background sweep.
  • Wall clock or monotonic? Monotonic. An NTP adjustment must not resurrect or kill entries.
  • Single-threaded? No. Many threads share one cache, and on Python 3.13's free-threaded build there may be no GIL to hide behind.
  • Does overwriting a key count as an eviction? No. It is a replacement, and listeners hear it with its own cause.
  • Read-through? Yes: a loader fills misses, and concurrent misses for the same key share one load.

Functional

  • get(key, default) and put(key, value, ttl=None, size=None) in O(1).
  • delete, clear, peek (a read with no side effects) and key in cache.
  • Pluggable eviction: LRU, LFU, FIFO. A new policy is a new class.
  • Per-entry TTL with a config default. Expired entries are invisible and removed lazily. purge_expired() removes them all, and an optional Sweeper thread calls it on a timer.
  • Capacity by count and by size. An entry bigger than the whole cache is rejected.
  • Stats: hits, misses, puts, evictions, expirations, hit rate.
  • Removal listeners that receive the key, the value and a cause: capacity, expired, explicit or replaced.
  • A read_through decorator with single-flight loading. Loader failures surface as one typed error and are not cached.

Non-functional

  • Thread-safe. Each public call is atomic.
  • Listener callbacks never run under the cache lock.
  • Time comes from an injected clock. No time.monotonic() in domain logic.
  • Every tunable lives in a validated config dataclass.
  • Typed exception hierarchy; no bare except.
  • Stdlib only.

The 2026 interview angle. The problem has not changed in years, but the follow-ups have. Interviewers now frame it around an LLM gateway caching prompt responses, or a feature store caching embeddings. Those values are expensive to produce and very uneven in size. That is why capacity by size, stampede protection and stats are no longer bonus points; they are the expected baseline. Expect a question about free-threaded Python too. "The GIL makes dict operations atomic" was always a shaky argument. On a python3.13t build it is simply wrong, so the lock has to be explicit. Section 9 rehearses the goalpost moves: shard it, make it distributed, serve stale while refreshing, cache the misses.

5. Key design decisions

  1. A dict plus a doubly linked list, and why both. A dict alone finds a key in O(1) but has no notion of "oldest". A list alone knows the order, but finding a key in it is O(n). Put them together: the dict maps each key to its node, and the node sits in a doubly linked list ordered by recency. A hit becomes "find the node through the dict, unlink it, push it to the front". Each of those is a few pointer swaps. Eviction is "take the node at the back". It must be doubly linked, because unlinking a node from the middle needs its predecessor, and a singly linked list would have to walk to find it.
  2. Then admit the shortcut. collections.OrderedDict is a dict plus a doubly linked list, written in C. move_to_end(key) and popitem(last=False) give you LRU in a handful of lines. In an interview, write the hand-made version first, because that is the data-structure question being asked. Then say "in production I'd use OrderedDict" and show it. This chapter ships both, and one test proves they agree.
  3. The policy owns order; the cache owns values. Eviction is a Strategy with four hooks: on_insert, on_access, on_remove, victim. The cache never knows whether it is running LRU or LFU. LFU stays O(1) too: one linked list per access count, plus a pointer to the lowest count. Adding a policy means adding a class. The cache does not change.
  4. Expiry is lazy, sweeping is optional. get checks the entry's deadline and removes it on the spot if it has passed. That costs O(1) and needs no thread. The blind spot is the entry nobody reads again: it sits in memory until capacity pressure evicts it. Sweeper closes the gap with a periodic O(n) purge_expired(). It is a separate class you opt into, because plenty of caches never need it.
  5. Two capacities, one eviction loop. Before inserting, _make_room evicts victims until both the count limit and the size limit leave room for the newcomer. Evicting before inserting matters. Otherwise LFU would evict the brand-new entry, which always has the lowest count. Sizing is injected (sizer=len for bytes), so the cache never guesses what "size" means.
  6. One lock, and listeners run outside it. A single threading.Lock guards the dict, the policy, the size total and the counters, so every public call is atomic. Removals are collected into a list while the lock is held. Listeners are called after it is released. A slow listener cannot stall readers, and a listener that calls back into the cache cannot deadlock it.
  7. Coarse lock now; finer later, on purpose. A single lock is simple and obviously correct, and an in-memory dict operation is fast enough that contention rarely shows up first. The finer options all cost something. Sharding into N independent caches makes LRU approximate and splits the capacity. Lock-free reads with buffered recency updates (Caffeine's approach) are far more complex. Start coarse, measure, then shard. Section 9 shows how.
  8. Single-flight for stampedes. On a miss, the first thread for a key becomes the leader and calls the loader. Every later thread for that key waits on the leader's Future. The leader stores the value before leaving the in-flight map, and newcomers re-check the cache inside the loader's lock. So no window exists in which a second load can start.
  9. The clock is injected, and it is monotonic. TTL is a duration, not a calendar time. time.monotonic() never jumps when the wall clock is corrected. FakeClock lets every TTL test move time forward by exactly the amount it needs, with no sleep.

Patterns, and why each earns its place. Strategy for eviction: the order rule varies independently of storage. Observer for removal listeners: write-back, metrics and cleanup subscribe without the cache knowing about any of them. Decorator for read-through: @read_through(cache) wraps a plain fetch function, so the fetch stays testable on its own. Config-driven factory (make_policy): a deployment can pick a policy by name, and code can still inject an instance directly.

Step 2 — Configuration: every limit in one place

Goal: one frozen dataclass holding both capacities, the default TTL, the policy name and the sweep interval, validated on construction.

Type cache/config.py:

"""Configuration: every tunable the cache has, in one validated place.

No method in the package contains a literal capacity, TTL or interval. Change
a number here and the behaviour follows; a bad number fails at construction,
not three hours into production.
"""
from dataclasses import dataclass
from enum import Enum

from .errors import CacheConfigError


class EvictionKind(Enum):
    LRU = "lru"
    LFU = "lfu"
    FIFO = "fifo"


@dataclass(frozen=True)
class CacheConfig:
    max_entries: int = 1024            # capacity by count
    max_size: int | None = None        # capacity by size units; None = count only
    default_ttl: float | None = None   # seconds; None = entries never expire
    eviction: EvictionKind = EvictionKind.LRU
    sweep_interval: float = 30.0       # seconds between background sweeps

    def __post_init__(self) -> None:
        if self.max_entries < 1:
            raise CacheConfigError(f"max_entries must be >= 1, got {self.max_entries}")
        if self.max_size is not None and self.max_size < 1:
            raise CacheConfigError(f"max_size must be >= 1, got {self.max_size}")
        if self.default_ttl is not None and self.default_ttl <= 0:
            raise CacheConfigError(f"default_ttl must be > 0, got {self.default_ttl}")
        if self.sweep_interval <= 0:
            raise CacheConfigError(
                f"sweep_interval must be > 0, got {self.sweep_interval}")

What to notice. max_size=None and default_ttl=None mean "off", not zero. Zero is rejected, because a zero TTL or a zero-size cache is almost always a typo. The policy is named by an enum rather than a string, so a misspelled policy fails at import time, not at the first eviction.

Step 3 — The clock

Goal: type a monotonic clock interface, the real implementation, and a fake that tests move by hand.

Type cache/clock.py:

"""Injectable clock. Domain code never calls time.monotonic() directly.

TTLs are measured on a monotonic clock, not wall time: if an operator moves
the system clock back an hour, entries must not suddenly live an hour longer.
Tests use FakeClock and move time forward by hand.
"""
import threading
import time
from abc import ABC, abstractmethod


class Clock(ABC):
    @abstractmethod
    def now(self) -> float:
        """Seconds on a clock that never goes backwards."""


class SystemClock(Clock):
    def now(self) -> float:
        return time.monotonic()


class FakeClock(Clock):
    """A clock that only moves when a test says so. Safe to share across threads."""

    def __init__(self, start: float = 0.0) -> None:
        self._lock = threading.Lock()  # guards _now
        self._now = start

    def now(self) -> float:
        with self._lock:
            return self._now

    def advance(self, seconds: float) -> None:
        if seconds < 0:
            raise ValueError("a monotonic clock cannot go backwards")
        with self._lock:
            self._now += seconds

What to notice. The method is now(), returning float seconds, not a datetime. A TTL is "60 seconds from now", which is arithmetic on a number. FakeClock has its own lock, because the concurrency tests share it across threads. advance refuses negative values, because a monotonic clock that runs backwards is not monotonic.

Checkpoint:

python3 -c "

print(c.now())"

Step 4 — The doubly linked list

Goal: type the O(1) half of LRU by hand: a list with sentinel head and tail nodes.

Type cache/linked_list.py:

"""A doubly linked list with sentinel nodes: the O(1) half of an LRU cache.

A dict finds a key's node in O(1). This list then moves, unlinks or appends
that node in O(1), because every node knows both neighbours. Two sentinels
(head and tail) mean the list is never "really" empty, so no method needs an
if-branch for the first or last node.

Order convention: front = most recently touched, back = next to go.
"""
from collections.abc import Iterator


class Node[K]:
    __slots__ = ("key", "prev", "next")

    def __init__(self, key: K) -> None:
        self.key = key
        self.prev: Node[K] | None = None
        self.next: Node[K] | None = None


class DoublyLinkedList[K]:
    """Not thread-safe on its own; the owning cache holds the lock."""

    def __init__(self) -> None:
        self._head: Node[K] = Node(None)  # type: ignore[arg-type]  # sentinel
        self._tail: Node[K] = Node(None)  # type: ignore[arg-type]  # sentinel
        self._head.next = self._tail
        self._tail.prev = self._head
        self._length = 0

    def __len__(self) -> int:
        return self._length

    def push_front(self, node: Node[K]) -> None:
        first = self._head.next
        node.prev, node.next = self._head, first
        self._head.next = node
        first.prev = node  # type: ignore[union-attr]
        self._length += 1

    def remove(self, node: Node[K]) -> None:
        node.prev.next = node.next  # type: ignore[union-attr]
        node.next.prev = node.prev  # type: ignore[union-attr]
        node.prev = node.next = None
        self._length -= 1

    def move_to_front(self, node: Node[K]) -> None:
        self.remove(node)
        self.push_front(node)

    def back(self) -> Node[K] | None:
        """The node at the back (least recently touched), or None if empty."""
        last = self._tail.prev
        return None if last is self._head else last

    def __iter__(self) -> Iterator[K]:
        """Keys from front (newest) to back (oldest)."""
        node = self._head.next
        while node is not self._tail:
            yield node.key  # type: ignore[union-attr]
            node = node.next  # type: ignore[union-attr]

What to notice. The sentinels are the trick. Because _head and _tail always exist, push_front and remove never ask "am I the first node?" or "is the list empty?". Those branches are where hand-written linked lists usually break. __slots__ on Node keeps each node small; a cache can hold millions. The list has no lock of its own. It is a data structure, and the cache that owns it decides the locking.

Checkpoint:

python3 -c "

for n in (a, b, c):
    lst.push_front(n)
print(list(lst), lst.back().key)
lst.move_to_front(a)
print(list(lst), lst.back().key)
lst.remove(b)

Step 5 — Eviction policies as a Strategy

Goal: type the EvictionPolicy ABC and four implementations: hand-written LRU, LFU, FIFO, and the OrderedDict shortcut.

Type cache/policies.py:

"""Eviction policies as a Strategy.

The cache owns the values. A policy owns only the *order* of keys and answers
one question: "if something must go, which key?" The cache tells the policy
about every insert, access and removal, and asks victim() when it is full.

Every method here is O(1). None of them lock: the cache calls them while it
holds its own lock, so a policy never sees two threads at once.
"""
from abc import ABC, abstractmethod
from collections import OrderedDict
from collections.abc import Callable

from .config import EvictionKind
from .errors import CacheError
from .linked_list import DoublyLinkedList, Node


class EvictionPolicy[K](ABC):
    @abstractmethod
    def on_insert(self, key: K) -> None: ...

    @abstractmethod
    def on_access(self, key: K) -> None: ...

    @abstractmethod
    def on_remove(self, key: K) -> None: ...

    @abstractmethod
    def victim(self) -> K:
        """The key to evict next. Raises CacheError if nothing is tracked."""


class LRUPolicy[K](EvictionPolicy[K]):
    """Least recently used: a dict of key -> node, plus a doubly linked list."""

    def __init__(self) -> None:
        self._nodes: dict[K, Node[K]] = {}
        self._order: DoublyLinkedList[K] = DoublyLinkedList()

    def on_insert(self, key: K) -> None:
        node = Node(key)
        self._nodes[key] = node
        self._order.push_front(node)

    def on_access(self, key: K) -> None:
        self._order.move_to_front(self._nodes[key])

    def on_remove(self, key: K) -> None:
        self._order.remove(self._nodes.pop(key))

    def victim(self) -> K:
        last = self._order.back()
        if last is None:
            raise CacheError("victim() called on an empty LRU policy")
        return last.key


class FIFOPolicy[K](LRUPolicy[K]):
    """First in, first out: LRU's list, but a read never changes the order."""

    def on_access(self, key: K) -> None:
        pass


class LFUPolicy[K](EvictionPolicy[K]):
    """Least frequently used, O(1): one linked list per access count.

    Ties within the lowest count go to the least recently used key, because
    each bucket is itself an LRU list.
    """

    def __init__(self) -> None:
        self._nodes: dict[K, Node[K]] = {}
        self._counts: dict[K, int] = {}
        self._buckets: dict[int, DoublyLinkedList[K]] = {}
        self._min_count = 0

    def _bucket(self, count: int) -> DoublyLinkedList[K]:
        return self._buckets.setdefault(count, DoublyLinkedList())

    def _unlink(self, key: K) -> int:
        count = self._counts[key]
        bucket = self._buckets[count]
        bucket.remove(self._nodes[key])
        if not bucket:
            del self._buckets[count]
        return count

    def on_insert(self, key: K) -> None:
        node = Node(key)
        self._nodes[key] = node
        self._counts[key] = 1
        self._bucket(1).push_front(node)
        self._min_count = 1

    def on_access(self, key: K) -> None:
        count = self._unlink(key)
        if count == self._min_count and count not in self._buckets:
            self._min_count = count + 1
        self._counts[key] = count + 1
        self._bucket(count + 1).push_front(self._nodes[key])

    def on_remove(self, key: K) -> None:
        self._unlink(key)
        del self._nodes[key], self._counts[key]

    def victim(self) -> K:
        if not self._buckets:
            raise CacheError("victim() called on an empty LFU policy")
        if self._min_count not in self._buckets:
            # Only after a removal emptied the lowest bucket; rare, and
            # bounded by the number of distinct counts, not by cache size.
            self._min_count = min(self._buckets)
        return self._buckets[self._min_count].back().key  # type: ignore[union-attr]


class OrderedDictLRUPolicy[K](EvictionPolicy[K]):
    """The stdlib shortcut: OrderedDict is a dict plus a doubly linked list."""

    def __init__(self) -> None:
        self._order: OrderedDict[K, None] = OrderedDict()

    def on_insert(self, key: K) -> None:
        self._order[key] = None

    def on_access(self, key: K) -> None:
        self._order.move_to_end(key)

    def on_remove(self, key: K) -> None:
        del self._order[key]

    def victim(self) -> K:
        if not self._order:
            raise CacheError("victim() called on an empty LRU policy")
        return next(iter(self._order))


POLICY_FACTORIES: dict[EvictionKind, Callable[[], EvictionPolicy]] = {
    EvictionKind.LRU: LRUPolicy,
    EvictionKind.LFU: LFUPolicy,
    EvictionKind.FIFO: FIFOPolicy,
}


def make_policy(kind: EvictionKind) -> EvictionPolicy:
    """Build the policy a config names. Inject an instance to bypass this."""
    return POLICY_FACTORIES[kind]()

What to notice. FIFOPolicy is LRUPolicy with one method overridden to do nothing. A read never reorders, so the back of the list is always the oldest insert. LFU is the interesting one. A key's count moves it from bucket n to bucket n + 1. _min_count only ever needs to step up by one on access, because the key that emptied the lowest bucket is now in the next one. A removal can leave _min_count stale, so victim() repairs it lazily. Compare OrderedDictLRUPolicy with LRUPolicy: same behaviour, about a quarter of the code.

Checkpoint — one access pattern, four different victims:

python3 -c "
from cache.policies import FIFOPolicy, LFUPolicy, LRUPolicy, OrderedDictLRUPolicy
for policy in (LRUPolicy(), OrderedDictLRUPolicy(), LFUPolicy(), FIFOPolicy()):
    for key in 'cba':
        policy.on_insert(key)
    for key in 'aabc':
        policy.on_access(key)
    print(f'{type(policy).__name__:<20} evicts {policy.victim()}')"

Output:

LRUPolicy            evicts a
OrderedDictLRUPolicy evicts a
LFUPolicy            evicts b
FIFOPolicy           evicts c

Work it by hand once. Inserted c, b, a; then read a, a, b, c. The least recent touch is a, so LRU evicts a. Counts are a=3, b=2, c=2; the tie between b and c goes to the less recent b, so LFU evicts b. FIFO ignores reads and evicts the first insert, c.

Step 6 — Stats

Goal: type the counters the cache mutates and the frozen snapshot callers read.

Type cache/stats.py:

"""Hit/miss/eviction counters, and the frozen snapshot callers get to see.

The cache mutates a StatsCounter under its own lock. Callers only ever get a
CacheStats snapshot, so a dashboard reading stats can never see a half-updated
set of numbers or change them by accident.
"""
from dataclasses import asdict, dataclass


@dataclass(frozen=True)
class CacheStats:
    hits: int = 0
    misses: int = 0
    puts: int = 0
    evictions: int = 0     # removed to make room (count or size)
    expirations: int = 0   # removed because the TTL ran out

    @property
    def requests(self) -> int:
        return self.hits + self.misses

    @property
    def hit_rate(self) -> float:
        return self.hits / self.requests if self.requests else 0.0


@dataclass
class StatsCounter:
    """Mutable twin of CacheStats. Not thread-safe; the cache's lock guards it."""

    hits: int = 0
    misses: int = 0
    puts: int = 0
    evictions: int = 0
    expirations: int = 0

    def snapshot(self) -> CacheStats:
        return CacheStats(**asdict(self))

What to notice. Two classes for one idea, on purpose. StatsCounter is mutable and lives inside the lock. CacheStats is frozen and leaves the cache. A metrics exporter can hold a snapshot for as long as it likes. It will never see hits from one moment and misses from the next.

Step 7 — Removal listeners

Goal: type the notification, its cause, and the listener interface.

Type cache/listeners.py:

"""Removal notifications: who left the cache, and why.

A listener hears about every removal, with its cause. Use it to write dirty
entries back, release resources, or feed metrics. Listeners run *after* the
cache releases its lock, so a slow listener never blocks other readers.
"""
import logging
from abc import ABC, abstractmethod
from dataclasses import dataclass
from enum import Enum

log = logging.getLogger(__name__)


class RemovalCause(Enum):
    CAPACITY = "capacity"   # evicted by the policy to make room
    EXPIRED = "expired"     # TTL ran out (found lazily or by the sweeper)
    EXPLICIT = "explicit"   # delete() or clear()
    REPLACED = "replaced"   # put() overwrote the key


@dataclass(frozen=True)
class RemovalNotification[K, V]:
    key: K
    value: V
    cause: RemovalCause


class EvictionListener[K, V](ABC):
    @abstractmethod
    def on_removal(self, notification: RemovalNotification[K, V]) -> None: ...


class LoggingListener[K, V](EvictionListener[K, V]):
    """Logs every removal at DEBUG. Handy as a default while debugging."""

    def on_removal(self, notification: RemovalNotification[K, V]) -> None:
        log.debug("removed %r (%s)", notification.key, notification.cause.value)

What to notice. RemovalCause is what makes listeners useful. A write-back listener flushes on CAPACITY and EXPIRED, but not on REPLACED, where the new value supersedes the old. A metrics listener counts each cause separately. Without the cause, every listener would have to guess.

Step 8 — The cache

Goal: type Cache, which ties it all together: O(1) get and put, lazy TTL, both capacities, stats, and listeners fired outside the lock.

Type cache/cache.py:

"""The cache itself: O(1) get/put, TTL, two capacity limits, stats, listeners.

Division of labour:
  - the dict below holds values (key -> entry), so lookup is O(1);
  - the policy holds the order of keys and picks eviction victims in O(1);
  - the clock says what time it is; the sizer says how big a value is;
  - listeners hear about removals after the lock is released.

Expiry is lazy: get() notices a dead entry and removes it on the spot.
purge_expired() does the same for every entry; a Sweeper calls it on a timer.

Thread safety: one lock guards _entries, _total_size, _stats and the policy.
Every public method takes it, so each call is atomic. Listener callbacks are
collected under the lock and fired after it is released.
"""
import logging
import threading
from collections.abc import Callable, Iterable
from dataclasses import dataclass
from typing import Final

from .clock import Clock, SystemClock
from .config import CacheConfig
from .errors import EntryTooLargeError, InvalidEntryError
from .listeners import EvictionListener, RemovalCause, RemovalNotification
from .policies import EvictionPolicy, make_policy
from .stats import CacheStats, StatsCounter

log = logging.getLogger(__name__)


class _Missing:
    """Sentinel type: lets None be a legitimate cached value."""

    def __repr__(self) -> str:
        return "MISSING"


MISSING: Final = _Missing()


def unit_size(value: object) -> int:
    """Default sizer: every entry counts as 1, so max_size acts like a count."""
    return 1


@dataclass(slots=True)
class _Entry[V]:
    value: V
    size: int
    expires_at: float | None  # monotonic seconds; None = never

    def is_expired(self, now: float) -> bool:
        return self.expires_at is not None and now >= self.expires_at


class Cache[K, V]:
    def __init__(
        self,
        config: CacheConfig | None = None,
        *,
        policy: EvictionPolicy[K] | None = None,
        clock: Clock | None = None,
        sizer: Callable[[V], int] | None = None,
        listeners: Iterable[EvictionListener[K, V]] = (),
    ) -> None:
        self._config = config or CacheConfig()
        self._policy = policy or make_policy(self._config.eviction)
        self._clock = clock or SystemClock()
        self._sizer = sizer or unit_size
        self._listeners = list(listeners)
        self._lock = threading.Lock()  # guards everything below this line
        self._entries: dict[K, _Entry[V]] = {}
        self._total_size = 0
        self._stats = StatsCounter()

    @property
    def config(self) -> CacheConfig:
        return self._config

    # -- reads ----------------------------------------------------------

    def get(self, key: K, default: V | None = None) -> V | None:
        """Value for key, or default. Counts a hit or a miss; refreshes recency."""
        removed: list[RemovalNotification[K, V]] = []
        with self._lock:
            entry = self._entries.get(key)
            if entry is not None and entry.is_expired(self._clock.now()):
                self._remove(key, RemovalCause.EXPIRED, removed)
                entry = None
            if entry is None:
                self._stats.misses += 1
                result = default
            else:
                self._stats.hits += 1
                self._policy.on_access(key)
                result = entry.value
        self._notify(removed)
        return result

    def peek(self, key: K, default: V | None = None) -> V | None:
        """Like get(), with no side effects: no stats, no recency, no removal."""
        with self._lock:
            entry = self._entries.get(key)
            if entry is None or entry.is_expired(self._clock.now()):
                return default
            return entry.value

    def __contains__(self, key: object) -> bool:
        return self.peek(key, MISSING) is not MISSING  # type: ignore[arg-type]

    def __len__(self) -> int:
        """Stored entries, including expired ones not yet noticed."""
        with self._lock:
            return len(self._entries)

    @property
    def total_size(self) -> int:
        with self._lock:
            return self._total_size

    def stats(self) -> CacheStats:
        with self._lock:
            return self._stats.snapshot()

    # -- writes ---------------------------------------------------------

    def put(self, key: K, value: V, *, ttl: float | None = None,
            size: int | None = None) -> None:
        """Store value. ttl overrides config.default_ttl; size overrides the sizer.

        Overwriting a key replaces the entry as if it were new: it goes to the
        front of LRU and FIFO order and restarts at count 1 under LFU.
        """
        if ttl is not None and ttl <= 0:
            raise InvalidEntryError(f"ttl must be > 0, got {ttl}")
        size = self._sizer(value) if size is None else size
        if size < 0:
            raise InvalidEntryError(f"size must be >= 0, got {size}")
        max_size = self._config.max_size
        if max_size is not None and size > max_size:
            raise EntryTooLargeError(
                f"entry of size {size} can never fit in max_size {max_size}")
        ttl = self._config.default_ttl if ttl is None else ttl

        removed: list[RemovalNotification[K, V]] = []
        with self._lock:
            now = self._clock.now()
            if key in self._entries:
                self._remove(key, RemovalCause.REPLACED, removed)
            self._make_room(size, removed)
            self._entries[key] = _Entry(
                value, size, None if ttl is None else now + ttl)
            self._total_size += size
            self._policy.on_insert(key)
            self._stats.puts += 1
        self._notify(removed)

    def delete(self, key: K) -> bool:
        """Remove key. True if it was there (even if already expired)."""
        removed: list[RemovalNotification[K, V]] = []
        with self._lock:
            if key in self._entries:
                self._remove(key, RemovalCause.EXPLICIT, removed)
        self._notify(removed)
        return bool(removed)

    def clear(self) -> None:
        removed: list[RemovalNotification[K, V]] = []
        with self._lock:
            for key in list(self._entries):
                self._remove(key, RemovalCause.EXPLICIT, removed)
        self._notify(removed)

    def purge_expired(self) -> int:
        """Remove every expired entry now. O(n); meant for a background sweeper."""
        removed: list[RemovalNotification[K, V]] = []
        with self._lock:
            now = self._clock.now()
            dead = [k for k, e in self._entries.items() if e.is_expired(now)]
            for key in dead:
                self._remove(key, RemovalCause.EXPIRED, removed)
        self._notify(removed)
        if removed:
            log.debug("purged %d expired entries", len(removed))
        return len(removed)

    # -- internals (call with the lock held) ----------------------------

    def _make_room(self, incoming_size: int,
                   removed: list[RemovalNotification[K, V]]) -> None:
        max_size = self._config.max_size
        while self._entries and (
            len(self._entries) + 1 > self._config.max_entries
            or (max_size is not None
                and self._total_size + incoming_size > max_size)
        ):
            self._remove(self._policy.victim(), RemovalCause.CAPACITY, removed)

    def _remove(self, key: K, cause: RemovalCause,
                removed: list[RemovalNotification[K, V]]) -> None:
        entry = self._entries.pop(key)
        self._total_size -= entry.size
        self._policy.on_remove(key)
        if cause is RemovalCause.CAPACITY:
            self._stats.evictions += 1
        elif cause is RemovalCause.EXPIRED:
            self._stats.expirations += 1
        removed.append(RemovalNotification(key, entry.value, cause))

    # -- listeners (call WITHOUT the lock) ------------------------------

    def _notify(self, removed: list[RemovalNotification[K, V]]) -> None:
        for notification in removed:
            for listener in self._listeners:
                try:
                    listener.on_removal(notification)
                except Exception:
                    # One broken listener must not break the cache or starve
                    # the others. Log it with the traceback and move on.
                    log.exception("eviction listener %r failed on %r",
                                  listener, notification.key)

What to notice. Follow one put through. Arguments are validated before the lock: a bad TTL never makes another thread wait. Under the lock, an existing key is removed as REPLACED, _make_room evicts until the newcomer fits, and only then is the entry inserted. Every removal funnels through _remove. It is the one place that keeps the dict, the size total, the policy and the stats in step. Every removal ends up in the removed list, and _notify runs after the with block ends. peek deliberately has no side effects, which the loader relies on in Step 10. Finally, MISSING: because get(key, MISSING) can tell "absent" from "cached None", None is a perfectly good value to cache.

Step 9 — The optional sweeper

Goal: type a background thread that purges expired entries on an interval, and stops cleanly.

Type cache/sweeper.py:

"""Optional background sweeper: purges expired entries on a timer.

Lazy expiry alone has a blind spot. An entry nobody reads again is never
looked at, so it sits in memory until capacity pressure evicts it. The
sweeper closes that gap. It is optional because many caches never need it.
"""
import logging
import threading
from types import TracebackType

from .cache import Cache
from .errors import SweeperStateError

log = logging.getLogger(__name__)


class Sweeper:
    def __init__(self, cache: Cache, interval: float) -> None:
        if interval <= 0:
            raise ValueError(f"interval must be > 0, got {interval}")
        self._cache = cache
        self._interval = interval
        self._stop = threading.Event()
        self._thread: threading.Thread | None = None

    def sweep_once(self) -> int:
        """One pass. Tests call this directly for deterministic sweeps."""
        try:
            return self._cache.purge_expired()
        except Exception:
            # A background thread has no caller to raise to. If it died here,
            # sweeping would stop silently forever. Log loudly, try again later.
            log.exception("sweep failed; will retry next interval")
            return 0

    def start(self) -> None:
        if self._thread is not None:
            raise SweeperStateError("sweeper already started")
        self._thread = threading.Thread(
            target=self._run, name="cache-sweeper", daemon=True)
        self._thread.start()

    def stop(self, timeout: float | None = None) -> None:
        if self._thread is None:
            raise SweeperStateError("sweeper was never started")
        self._stop.set()
        self._thread.join(timeout)

    def _run(self) -> None:
        # Event.wait doubles as an interruptible sleep: stop() wakes it at once.
        while not self._stop.wait(self._interval):
            self.sweep_once()

    def __enter__(self) -> "Sweeper":
        self.start()
        return self

    def __exit__(self, exc_type: type[BaseException] | None,
                 exc: BaseException | None, tb: TracebackType | None) -> None:
        self.stop()

What to notice. self._stop.wait(interval) is the whole loop. It sleeps for the interval, but stop() wakes it instantly, so shutdown never waits out a 30-second sleep. The thread is a daemon, so a forgotten sweeper cannot keep the process alive. sweep_once catches Exception, logs it with the traceback and carries on. A background thread has no caller to raise to; if it died here, sweeping would stop silently. That is the one place in the package where a broad catch is correct.

Step 10 — Read-through with single-flight

Goal: type the loader that turns many concurrent misses for one key into exactly one call to the backing store, and the decorator that wraps it.

Type cache/loader.py:

"""Read-through loading with single-flight, so a miss never becomes a stampede.

The stampede: a hot key expires, and 500 requests miss at the same instant.
Without coordination, all 500 call the database for the same row. With
single-flight, the first thread to miss becomes the *leader* and calls the
loader. The other 499 become *followers* and wait on the leader's Future.
One load, 500 answers.

Lock order is always loader lock -> cache lock, never the reverse, so the two
locks cannot deadlock. The loader itself runs with no lock held at all.
"""
import functools
import logging
import threading
from collections.abc import Callable
from concurrent.futures import Future

from .cache import MISSING, Cache
from .errors import LoadError

log = logging.getLogger(__name__)


class SingleFlightLoader[K, V]:
    def __init__(self, cache: Cache[K, V], loader: Callable[[K], V], *,
                 ttl: float | None = None) -> None:
        self._cache = cache
        self._loader = loader
        self._ttl = ttl
        self._lock = threading.Lock()  # guards _in_flight and _load_count
        self._in_flight: dict[K, Future[V]] = {}
        self._load_count = 0

    @property
    def load_count(self) -> int:
        """How many times the underlying loader has actually been called."""
        with self._lock:
            return self._load_count

    def get(self, key: K) -> V:
        value = self._cache.get(key, MISSING)
        if value is not MISSING:
            return value  # type: ignore[return-value]

        with self._lock:
            # Re-check: a leader may have finished between our miss and now.
            value = self._cache.peek(key, MISSING)
            if value is not MISSING:
                return value  # type: ignore[return-value]
            future = self._in_flight.get(key)
            is_leader = future is None
            if is_leader:
                future = Future()
                self._in_flight[key] = future
                self._load_count += 1

        if not is_leader:
            return future.result()  # blocks; re-raises the leader's LoadError

        try:
            value = self._loader(key)
            # Store BEFORE leaving the in-flight map, so a late arrival
            # finds the value in the cache instead of starting a second load.
            self._cache.put(key, value, ttl=self._ttl)
        except Exception as exc:
            error = LoadError(f"loading {key!r} failed: {exc}")
            error.__cause__ = exc
            future.set_exception(error)
            raise error from exc
        else:
            future.set_result(value)
            log.debug("loaded %r", key)
            return value
        finally:
            if not future.done():
                # Only on BaseException (e.g. KeyboardInterrupt): never leave
                # followers blocked on a Future nobody will resolve.
                future.set_exception(LoadError(f"loading {key!r} was aborted"))
            with self._lock:
                del self._in_flight[key]


def read_through[K, V](cache: Cache[K, V], *, ttl: float | None = None
                       ) -> Callable[[Callable[[K], V]], Callable[[K], V]]:
    """Decorator: turn a one-argument fetch function into a cached one.

        @read_through(cache, ttl=30)
        def load_user(user_id): ...

    The wrapped function keeps its name and docstring; the SingleFlightLoader
    behind it is reachable as wrapper.single_flight (for load_count in tests).
    """
    def decorate(fetch: Callable[[K], V]) -> Callable[[K], V]:
        flight = SingleFlightLoader(cache, fetch, ttl=ttl)

        @functools.wraps(fetch)
        def wrapper(key: K) -> V:
            return flight.get(key)

        wrapper.single_flight = flight  # type: ignore[attr-defined]
        return wrapper

    return decorate

What to notice. Three details carry the correctness. First, the re-check: a thread that missed takes the loader lock and peeks again, because a leader may have finished in between. Second, the order inside the leader: put into the cache, then leave the in-flight map, so a late arrival finds one or the other, never neither. Third, the finally. Whatever happens, the in-flight entry is removed and the Future is resolved, so no follower can block forever. Failures are wrapped in LoadError with the original as __cause__, and they are not cached. The next call retries.

Honest limits. One lock serializes every call. That is fine for most services and a bottleneck for a very hot one (see the sharding follow-up). len() counts expired entries that nobody has noticed yet. purge_expired() is O(n) under the lock; a huge cache would want a timer wheel or a heap of deadlines. Overwriting a key resets its LFU count. The loader caches only successes, so a key whose source keeps failing is retried on every call.

9. Common interview follow-ups

Why a doubly linked list, not a singly linked one? Unlinking a node from the middle needs its predecessor. With only next pointers, you would walk the list to find it, and get would become O(n). The prev pointer is what keeps a hit O(1).

Why not just functools.lru_cache? It is excellent for pure functions, and you should say so. But it has no TTL, no size-based capacity, no listeners, no explicit invalidation of one key, and no single-flight. It also keys on the call's arguments, not on a business key. This chapter's cache is for data that goes stale.

Lazy expiry or eager? Lazy is O(1) and needs no thread. Its cost is memory held by dead entries nobody reads. Eager (the sweeper) frees memory but costs an O(n) scan per interval. Most real caches do both, which is what this design offers.

Goalpost: "Lock contention is the bottleneck. Fix it." Shard. Build N independent Cache instances, each with its own lock and policy, and route by hash(key) % N. Contention drops roughly N-fold. Two things are sacrificed. LRU becomes per-shard, so the globally oldest entry may survive while a fresher one in a full shard is evicted. And capacity splits evenly, so one hot shard can evict while others sit half empty. The Cache class does not change; a ShardedCache wraps N of them. That is stretch task 1.

Goalpost: "Now run it on 20 app servers." Each process keeps its own cache, so the problem becomes invalidation. Options, cheapest first: short TTLs and accept staleness. Publish invalidation messages (Redis pub/sub, Kafka) and have each node delete on receipt. Or move to a shared remote cache such as Redis and keep this one as a small L1 in front of it. The design change is a listener or subscriber that calls delete. The cache core is untouched.

Goalpost: "Never block a request on a refresh: serve stale while revalidating." Give each entry two deadlines: a soft one (refresh after) and a hard one (never serve after). Between the two, get returns the stale value and asks the SingleFlightLoader to refresh in the background. The single-flight map already guarantees only one refresh per key. The change is one more field on _Entry and a background executor in the loader.

Goalpost: "The database keeps getting hammered for keys that don't exist." Negative caching. When the loader returns "not found", store a NOT_FOUND sentinel with a short TTL, and have the wrapper translate it back. Keep the negative TTL short, or a newly created record stays invisible.

Goalpost: "LRU is getting thrashed by one-off scans." A single big scan pushes every hot key out of LRU. Answer with a new policy class. One option is an admission filter (TinyLFU): a newcomer gets in only if it is likely to be used more than the victim. Another is segmented LRU, where new keys wait in a probation segment. The Strategy seam means no edits to Cache.

Why do listeners run outside the lock? Two reasons. A slow listener (say, a write-back to disk) would otherwise block every reader. And a listener that calls back into the cache would deadlock on a non-reentrant lock. The test suite pins the second case.

Why a monotonic clock? TTL measures elapsed time. Wall-clock time jumps when NTP corrects it or when daylight saving changes. With time.time(), a backwards correction would keep entries alive too long, and a forward one would expire everything at once.

How do you cache a function with several arguments? Give the decorator a key_fn that builds a hashable key from *args, **kwargs (a tuple works). Keep it explicit. Hashing arbitrary arguments silently is how two different calls end up sharing an entry.
